# Контекст и бюджеты: манифест сессии, быстрый путь, явные лимиты

Этап 08 добавляет три вещи к существующим ограниченным упаковщикам контекста ([EFFICIENCY](EFFICIENCY.md)) и режимам исполнения ([RUNTIME](RUNTIME.md)). Решения описаны в [ADR-0010](decisions/0010-context-manifest-fast-path-budgets.md).

## ContextManifest

Перед каждой нативной сессией Engine записывает манифест: что именно получила сессия. Манифест хранит только размеры, флаги и ссылки на неизменяемые evidence. Текста prompt, приватных путей и секретов в нём нет по построению.

```json
{
  "schemaVersion": 1,
  "kind": "context-manifest",
  "runId": "…",
  "stage": "developer",
  "node": "feature",
  "headSha": "…",
  "limitBytes": null,
  "totalBytes": 6700,
  "mandatory": { "contract": { "kind": "node-contract", "file": "node-contract-<sha256>.json", "sha256": "…", "bytes": 120, "headSha": "…" } },
  "sections": [
    { "name": "guidance", "bytes": 900, "mandatory": true },
    { "name": "instructions", "bytes": 300, "mandatory": true },
    { "name": "task-context", "bytes": 1500, "mandatory": true },
    { "name": "evidence", "bytes": 4000, "mandatory": false, "originalBytes": 52000, "truncated": true, "omitted": [{ "field": "analysis.files", "items": 40 }] }
  ],
  "references": [{ "kind": "analysis", "file": "analysis-<sha256>.json", "sha256": "…", "bytes": 120, "headSha": "…" }]
}
```

Манифест хранится вместе с записью сессии: `run.sessionAttempts[].manifest`, его SHA-256 — в `manifestSha256`. Отдельным файлом evidence он не сохраняется: подготовка защищённого каталога evidence на каждую сессию стоила бы дороже самой подготовки сессии. `totalBytes` равен `metrics.promptBytes` той же сессии.

Правила:

- Обязательные секции (`guidance`, `instructions`, `task-context`, `gates`) манифест не сокращает и не позволяет записать сокращёнными. Внутри `task-context` обязательный блок контракта (описание, область записи, acceptance) передаётся полностью, а необязательный блок (цель запуска, зависимости, источники) ограничен и может быть урезан упаковщиком контекста задачи; манифест этого урезания не показывает.
- Сессия с `task-context` обязана ссылаться на свой `node-contract`. Контракт содержит полные acceptance-критерии узла.
- Сокращённая секция обязана перечислить, что она потеряла (`omitted`). Молчаливого сокращения нет.
- Ссылка без корректного SHA-256 записывается как непроверяемая (`sha256: null`) и никогда не считается контрактом.

`manifestFreshness(manifest, { headSha, hashes })` отвечает, описывает ли манифест текущие входы:

| Статус | Когда |
| --- | --- |
| `fresh` | Evidence на месте с теми же хэшами, head не изменился |
| `stale` | Evidence цело, но head ушёл вперёд |
| `invalidated` | Файл evidence пропал или его хэш изменился |
| `unknown` | Текущее состояние не наблюдалось или версия манифеста не поддерживается |

## Быстрый путь

Вид `small_local`, локальный план и правила селекторов добавлены этапом 14 ([ADR-0016](decisions/0016-small-tasks.md)).

До обращения к Jev Engine локально, без модели, проверяет, является ли задача доказанно маленькой правкой нескольких названных файлов. Видов доказательства два: `style_only` — только файлы стилей, и `small_local` — от одного до трёх небольших исходников (среди них могут быть и стили). Доказательство требует всего сразу:

1. Текст задачи не длиннее 800 байт, без URL, абсолютных путей и `..`.
2. Цели правки — от одного до трёх путей, и все они — стили (`.css`, `.scss`, `.sass`, `.less`, `.styl`, `.pcss`) или исходники (`.js`, `.mjs`, `.cjs`, `.jsx`, `.ts`, `.mts`, `.cts`, `.tsx`, `.vue`, `.svelte`, `.html`, `.htm`), не в `node_modules/`, `vendor/`, `dist/`, `build/`, `coverage/` и не с именем секрета. Конфигурация и данные (`.json`, `.yaml`/`.yml`, `.toml`, `.ini`, `.env`, `.xml`, `.lock` и т. п.), манифесты, shell/PowerShell, SQL и миграции, CI и документация в список не входят: они меняют зависимости, данные, доставку или окружение, а это словарём не доказать. Имя конфигурации или данных в тексте — всегда сомнение, даже с ведущей точкой (`.pre-commit-config.yaml`).
3. Имена внутри команды — аргументы запуска, а не цели правки: интерпретатор с аргументами (`node verify.cjs`, `tsx x.ts`), менеджер пакетов (`npm run check`, `npm test`), глагол запуска с командой (`run X`, `execute X`, «запусти X», «выполни X») и многословная команда в обратных кавычках. Команда заканчивается на знаке конца предложения, переводе строки или союзе (and, then, и, затем…). Имя, которое встречается и вне команды, — цель. Одно имя в обратных кавычках — просто имя.
4. Любое другое слово, похожее на ссылку на файл, — сомнение: всё, что содержит `/` или точку не в конце слова (`.env`, `обработчик.js`, `icons.7z`, `src/server`, `v1.2`). Числа без единицы или с единицей CSS (`0.8`, `1.5rem`, `50%`) файлами не считаются; число с любым другим хвостом (`2.7z`) и записи вида `.5rem` или `16px/1.5` остаются сомнением. Слово с ведущей точкой без `/` — селектор класса (`.button`, `.card.is-active`, `.btn:hover`), только если все доказанные файлы — стили и это не отслеживаемый и не существующий в проекте файл, не известный dot-файл (`.env*`, `.git*`, `.npmrc`, имена на `rc`/`ignore`) и не имя секрета (`.pem`, `.key`). Рядом с исходником селектор — сомнение: он мог бы скрыть запрошенный файл. Селектор сам ничего не доказывает. Слово вида `Node.js` — имя исходника и потому должно быть отслеживаемым файлом. Файл без точки и без `/` в имени (`Makefile`) так распознать нельзя; от записи в него защищают сверка плана и проверка diff.
5. Каждый названный файл существует, отслеживается Git как обычный файл (не символическая ссылка и не подмодуль), не больше 64 КБ и не лежит в скрытом каталоге.
6. В тексте нет слов о поведении, данных, доступе и доставке (auth, login, password, token, secret, migration, deploy, release, install, upgrade, dependency, permission, key, api, refactor, rename, `npx`, `npm install/add/update/audit/ci…` и русские аналоги: миграция, деплой, релиз, установка, зависимости, пакет, ключи, права доступа и т. п.). Основы ищутся и внутри слов (`oauth`, `redeploy`). Запуск скрипта проекта (`npm test`, `npm run check`) маркером не является. «Обнови/обновить» и «удали/удалить» (update/remove/delete) содержимого названных файлов маркерами не являются; удаление самого названного файла («Delete src/a.mjs», «удали файл X», `rm X`) и создание файла («create/add a new file», «создай/добавь файл») — маркеры.
7. Явно не запрошен режим `standard` или `deep`.

При доказательстве выбирается профиль `quick` с `executionMode.source: "fast-path"`, `assessment: "not_requested"` и `run.fastPath.reason` (`style_only` или `small_local`): без Jev, Gemini и research. `run.fastPath.writePaths` — единственный список путей, которые план и фактический diff могут менять. Для стилей это названные файлы. Для `small_local` — названные файлы и конкретные пути регрессионных тестов, выведенные из названных скриптовых исходников: для `src/app.mjs` это `<база>.test<расш>` и `<база>.spec<расш>` в `tests/`, `test/`, рядом с исходником и в его `__tests__/`, с расширениями того же семейства (JS: `.js .mjs .cjs .jsx`; TS: `.ts .mts .cts .tsx`; Vue/Svelte — оба). Масок нет: конфигурация тестов, `package.json`, helpers и fixtures в список не попадают. Если задача ограничивает правку («only», «только», «не трогай», «do not edit/change…»), тестовых путей нет и тест не требуется.

План строится локально и детерминированно (`planSource: "fast-path"`) и проходит обычный валидатор: один узел `developer` с полным текстом задачи и `writePaths` из того же списка. Описание не требует менять каждый названный файл; acceptance требует регрессионный тест только при изменении поведения и только если тестовые пути есть. Сессии планировщика нет: нативных сессий две — исполнитель и свежее независимое read-only ревью. Проверки проекта и включённые gates выполняются как обычно; `kodo audit` остаётся complete (политика этапа `plan` записывается и для локального плана).

Любое сомнение возвращает обычный маршрут: оценка Jev, затем `quick`, `standard` или `deep`. Причина сомнения — код из списка: `mode_requested`, `task_invalid`, `task_too_long`, `url`, `path_not_relative`, `risk_marker`, `no_paths`, `non_style_path` (историческое имя: слово похоже на путь, но не допустимый файл стилей или исходника), `too_many_files`, `path_untracked`, `path_missing`, `path_not_file`, `file_too_large`.

Доказательство сверяется с планом и с diff. План, переданный файлом (`--plan`), должен писать только пути из `run.fastPath.writePaths`, буквально; иначе (включая glob) быстрый путь отзывается: бюджеты проекта восстанавливаются, выполняется обычная оценка, и план принимается как есть по правилам нового режима. Некорректный файл плана, слишком большой контракт узла и попытка заменить план после интеграции узлов отклоняются до сверки и быстрый путь не отзывают. Фактические изменения узла и ремонта проверок сверяются с тем же списком точным совпадением имён: каталог с именем разрешённого теста (`tests/app.test.mjs/x.json`) отклоняется как `scope_conflict`. В `run.fastPath` остаются `version` (2), `files`, `writePaths`, `reason`, исходные `budgets` и `revoked: "plan_outside_proof"`; у старого сохранённого доказательства без `writePaths` список — его `files`, без `reason` — `style_only`.

Список слов-маркеров — страховка, а не доказательство безопасности. Он не распознаёт рискованную задачу, описанную без этих слов; от неё защищают область записи узла, проверки и ревью.

## Явные лимиты запуска

```json
{ "budgets": { "sessions": 12, "contextBytes": 65536 } }
```

Ключ `budgets` в `kodo.config.json` необязателен. Без него лимитов нет, и поведение прежнее.

| Ключ | Диапазон | Что ограничивает |
| --- | --- | --- |
| `sessions` | 1–1000 | Число начатых нативных сессий одного Run, включая неудачные |
| `contextBytes` | 4096–4194304 | Размер контекста одной сессии по манифесту |

Лимит сохраняется в Run при создании. `resume`, новый цикл `--retry-failed` и параллельные исполнители его не расширяют: счётчик — это `run.sessionAttempts`, проверка и запись сессии выполняются одним синхронным шагом. Project retry создаёт новый Run с лимитами не больше прежних. Чтобы поднять лимит, нужен новый запуск.

Исчерпанный лимит сессий останавливает Run со статусом `blocked` и кодом `budget`. Контекст больше `contextBytes` останавливает Run с кодом `context_budget` до отправки: обязательный контекст не сокращается, чтобы уложиться. Отказ по лимиту — не сбой узла: попытка узла не расходуется, ремонт узла и research для него не запускаются. Так же проходит насквозь `context_budget` упаковщика evidence, когда обязательная часть evidence узла не помещается в его предел; раньше это было сбоем узла.

Лимит сессий проверяется в момент запуска сессии. Повторный `resume` или `--retry-failed` запуска с исчерпанным лимитом заново выполнит подготовку до сессии (маршрутизацию узла, локальные проверки и gates перед ревью, research перед ремонтом проверок) и снова получит отказ. Чтобы продолжить работу, нужен новый запуск с большим лимитом.

`headSha` манифеста — последний записанный head запуска на момент сессии. Для ревью после ремонта он может отставать от проверяемого commit; точный commit ревью записан в его собственной ссылке evidence.

Существующие лимиты `researchBudget`, `repairRounds`, `maxTasks` и `concurrency` не изменились.

## Что не измеряется

Байты контекста — не токены. Usage берётся только из того, что отдал нативный клиент; отсутствующий usage остаётся `null`, а не нулём ([metrics](../runtime/metrics.mjs)). Экономия токенов, квоты, денег и времени этим этапом не измерялась и не заявляется.

## Проверка

```powershell
node scripts/run-tests.mjs tests/fast-path.test.mjs tests/context-manifest.test.mjs tests/fast-path-engine.test.mjs
```

Все проверки offline: fake providers, настоящие Git и SQLite. Модели и платные вызовы не используются.
