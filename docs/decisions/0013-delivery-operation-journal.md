# ADR-0013: журнал операций доставки и привязка проверки установленного пакета

Статус: решение для MVP11. Приёмку этапа фиксирует [отчёт](../kodo-roadmap/phase-11.md), не этот ADR.

## Контекст

Аудит показал, что доставка уже читает удалённое состояние перед повтором: PR ищется по ветке, слияние подтверждается после любой ошибки команды, выпуск восстанавливается по метке владельца. Не хватало трёх вещей. Нигде не было записано, что внешнее действие начато: после сбоя между действием и сохранением квитанции запуск выглядел так, будто ничего не начиналось. Квитанция проверки установленного пакета не называла артефакт. Развёртывание не имело статуса вовсе.

## Решение и альтернативы

| Выбор | Альтернатива и причина отказа | Последствие |
| --- | --- | --- |
| Журнал — события запуска `delivery.operation` (намерение и исход) | Поле `operations` в сохранённой квитанции доставки: меняет форму квитанций, на которую опираются Director, аудит и сохранённые запуски | Квитанции не меняются; журнал переживает сбой, потому что событие пишется до действия |
| Четыре состояния, включая `uncertain` | Только «успех/неуспех»: сбой после успешного удалённого действия неотличим от неначатого | Неподтверждённое действие видно и не повторяется вслепую |
| Логика чтения удалённого состояния не менялась | Переписать восстановление вокруг журнала: существующее покрыто тестами и работает | Журнал наблюдает; решения по-прежнему принимает чтение удалённого состояния |
| `artifactSha256` в квитанции проверки и сверка перед публикацией | Считать привязку очевидной из порядка кода: при восстановлении проверка идёт на скачанных байтах, и это стоит записать | Изменён контракт квитанции (добавлено поле); старые квитанции читаются |
| `not_configured` и `not_run` вместо исполнения `commands.deploy` | Выполнять команды развёртывания: без адаптера нет проверки цели, отката и здоровья | Развёртывание не имитируется и не помечается пройденным |
| Не добавлять backup в job store | Backup перед созданием таблиц: миграция версии 1 только добавляет таблицы | Правило для будущих версий записано в [JOBS](../JOBS.md); неизвестная версия отклоняется |

## Границы

- Между чтением удалённого состояния и следующим действием другой процесс может изменить удалённое состояние. От этого защищают аренды очередей и `--match-head-commit`, а не журнал.
- Журнал не содержит вывода команд и текстов: только идентификаторы.
- Сводка `run.deliveryOperations` обновляется при завершении или остановке запуска; источник истины — события.

## Что отложено

Batch merge независимых изменений с изоляцией сломанного батча, жизненный цикл выпуска с состояниями `monitored` и `rollback-needed`, адаптеры развёртывания, canary и rollback, changelog из принятых изменений, единая квитанция выпуска вместо двух копий (`run.release` и `run.delivery.release`), версионирование и backup основной базы состояния.
