# ADR-0017: движок большого проекта — параллельно, быстро и правильно

Статус: решение этапов 15–16 (2026-11-24). Поведение описывают [RUNTIME](../RUNTIME.md), [T3-HOST](../T3-HOST.md), [QUALITY](../QUALITY.md), [ARCHITECTURE](../ARCHITECTURE.md) и [VERIFICATION](../VERIFICATION.md), не этот ADR. План и доказательства — [phase-15](../kodo-roadmap/phase-15.md).

## Контекст

Назначение Kodo по словам пользователя — достигать очень больших целей (пример масштаба: большая воксельная игра на Rust) многими агентами одновременно. Мерило — скорость и правильность на многовеховом проекте, а не одна задача.

В 1.0.1 фабрика доказана на малых JS-проектах и упирается в потолки:

- параллельность 1–5 задач (`next-wave --limit`, `drain --concurrency`, `concurrency` запуска), горизонт планировщика 24;
- `complete-task` держит `project:<id>` на всё время `task-fast`, слияние в ветку проекта ждёт одну аренду 120 с и падает `integration_busy`;
- `task-fast` сужает граф только для JS; для Rust каждый раз полный `cargo test` в холодном `target/`;
- интерфейсы модулей — только Markdown; Architecture Guardian проверяет только ESM; Behaviour Gate не видит `#[cfg(test)]` внутри `src/*.rs`; `quality.mjs` ломается на Cargo workspace;
- воркер начинает с чтения репозитория, а ремонт получает сырой хвост лога;
- спор гейта после двух раундов ремонта останавливает проект до человека; удалённых машин нет.

## Решение и альтернативы

| Выбор | Альтернатива и причина отказа | Последствие |
| --- | --- | --- |
| Профиль запуска (подписки и машины) задаёт пользователь на старте задачи; Kodo хранит его в состоянии проекта вне Git | Глобальная настройка: пользователь меняет подписки и машины от задачи к задаче | Фактическая параллельность = min(слоты подписок, слоты машин, независимые готовые задачи) |
| Скользящее окно с приоритетом критического пути вместо ожидания всей волны | Волновой барьер: самая медленная задача держит остальные слоты | Слот освобождается сдачей одной задачи; задачи с большим числом потомков идут первыми |
| Очередь интеграции в SQLite вместо одной аренды с таймаутом | Увеличить таймаут: очередь всё равно последовательна и падает под нагрузкой | Проверка задачи не держит блокировку проекта; слияние — короткая операция очереди |
| Компилируемый контрактный модуль Волны 0 и проверка графа модулей для Rust | Только Markdown-интерфейсы и ревью: дрейф типов находится поздно и дорого | Дрейф интерфейса — ошибка компиляции; обычная задача не может менять контракт |
| Детерминированные карты публичного API и структурированные пакеты ошибок в брифе | Отдать агенту весь репозиторий или сырые логи: дорого и шумно | Без вызовов модели; обязательный контракт не обрезается `ContextManifest` |
| Арбитр с другой подписки из профиля после исчерпания ремонта гейта | Больше раундов того же ремонта или сразу человек | Красный тест, архитектура и безопасность не обходятся арбитром; человек — только при `split_needed` |
| Удалённые воркеры через Git-транспорт служебных ссылок `refs/kodo/<projectId>/…` | Копирование файлов или общий диск: нет проверяемой истории | Kodo CLI по-прежнему не вызывает T3 (ADR-0015); целевую машину называет пользователь |

## Границы

- GPT и Claude — только подписочные клиенты; API-фолбэка нет. Ключи и учётные данные — вне Git, брифов, воркеров и журналов.
- Новое поведение фабрики — только при `project.execution.cadence === "wave"`; обычные запуски сохраняют прежние пределы по умолчанию.
- Оракульные и приёмочные тесты (`tests/*-oracle.test.mjs`, `tests/*-acceptance.test.mjs`), `migrationSql` и `CI_COMMAND_TIMEOUT_MS` не меняются.
- Пилоты строят оригинальную воксельную песочницу (своё название и облик), а не воссоздание существующей игры.
- Нет наблюдения — `unknown`/`NOT RUN`, а не PASS; отчёты не выдумывают чистую задержку модели и стоимость в USD.

- **15F.** Крейты могут обновлять зависимости в общем `Cargo.lock`. При конфликте только в lock интеграция регенерирует его offline и сверяет версии, источники и checksum с обоими родителями. Для их замены требуется отдельный владелец lock. Подробности в [RUNTIME](../RUNTIME.md#15f-координация-cargolock).
