# ADR-0010: манифест контекста, детерминированный быстрый путь и явные лимиты запуска

Статус: решение для MVP08. Приёмку этапа фиксирует [отчёт](../kodo-roadmap/phase-08.md), не этот ADR.

## Контекст

К этапу 08 в Kodo уже были ограниченные упаковщики evidence, несокращаемый контракт узла, режим `quick` без Gemini и research, счётчики сессий и nullable usage. Не было трёх вещей: единой записи о том, что получила сессия; способа обойтись без модели для очевидной локальной правки (оценка Jev вызывалась всегда); лимита на число сессий, который переживает `resume`.

## Решение и альтернативы

| Выбор | Альтернатива и причина отказа | Последствие |
| --- | --- | --- |
| Манифест хранит только размеры, флаги и хэш-ссылки | Хранить текст секций: манифест стал бы вторым местом утечки секретов и инструкций из найденных документов | Манифест безопасно показывать и сравнивать; текст остаётся в неизменяемых evidence |
| Манифест наблюдает, а не фильтрует входы | Отклонять сессию при ссылке непривычной формы: первая же версия так заблокировала ревью с существующими ссылками | Непроверяемая ссылка записывается с `sha256: null`; входы по-прежнему проверяет `assertEvidence` |
| Обязательный контекст не сокращается; при превышении явного лимита сессия отклоняется | Сокращать до лимита: acceptance узла мог бы пропасть молча | Код `context_budget` до отправки; пользователь поднимает лимит или делит задачу |
| Быстрый путь — только положительное локальное доказательство по названным файлам стилей | Классификатор по ключевым словам или модель: первое ненадёжно, второе и есть тот вызов, который хотим убрать | Узкое покрытие (стили), зато любое сомнение даёт обычный маршрут |
| План сверяется с доказательством, при выходе быстрый путь отзывается | Блокировать Run: пользователь получил бы отказ вместо работы | Одна лишняя сессия планировщика, затем обычный маршрут с бюджетами проекта |
| Быстрый путь реализован вне `resolveMode` | Новый режим `fast`: пришлось бы менять профили, сохранённые Run и отчёты | `selected: quick`, `source: fast-path`; существующие потребители режима не меняются |
| Лимит сессий считает `run.sessionAttempts` и проверяется синхронно перед записью сессии | Отдельный счётчик в SQLite: вторая запись о том же | Один источник; `resume`, retry-цикл и параллельные исполнители не обходят лимит |
| `budgets` необязателен, без значения по умолчанию | Лимит по умолчанию на режим: изменил бы поведение существующих запусков и тестов | Поведение без ключа прежнее |

## Границы

- Список слов-маркеров риска — страховка. Он не доказывает безопасность задачи и не заменяет область записи узла, проверки и ревью.
- Быстрый путь покрывает только стили. Другие «очевидно локальные» классы задач идут обычным маршрутом.
- Манифест привязан к head запуска на момент сессии. Он не доказывает, что исполнитель прочитал контекст.
- Лимиты действуют на один Run. Лимитов на Project и Milestone нет.

## Что отложено

Interface cards модулей, выбор контекста по AST и графу зависимостей, learned routing моделей, лимиты на Project/Milestone, адаптеры T3 Code и Orca, перенос TokenEconomizer, измерение токенов и сравнение plain/Kodo.
