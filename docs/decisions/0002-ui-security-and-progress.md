# ADR-0002: UI/security gates координатора и ограниченный контекст

**Дата:** 2026-11-03. **Статус:** решение задано integration-contract run `9fc232f4-c2fc-4d21-8822-9dcca700c309` и отражено в integration; исправление двух QA-регрессий подтверждено целевыми результатами координатора. Общий check/CI, merge, выпуск и deployment здесь не подтверждаются.

## Контекст

UI-инструменты требуют собственных процессов, профилей, секретов и наблюдаемого результата. Их присутствие в каталоге или ответ агента «готово» не доказывают работу интерфейса. Проверки должны относиться к той ревизии и конфигурации, которую доставляет Kodo. Нарастающие промпты и сырая история мешают передаче точной задачи и восстановлению после сбоя. Пользователь также ожидает постоянный чат-диспетчер и видимую реальную работу в поддерживающем это host-клиенте.

## Решение

- Сохранить Node.js 24 ESM, SQLite и существующие process/state/delivery порты. `runtime/tools.mjs` управляет отдельным внешним каталогом девяти закреплённых инструментов. Не добавлять registry-компоненты и default-skill IDs. Браузерные Python-пакеты живут в закрытом Python 3.12 venv, Semgrep — отдельно; импорт/метаданные не устанавливают пакеты.
- Выполнять шесть UI-адаптеров и два security scanner только координатором после build/test и до review. Worker получает stage-specific capabilities и область работы, без ключей и права запускать дополнительные агенты или UI-процессы. GPT/Claude используют подписочные клиенты; Google/TypeSafe остаются только в нужных bridge.
- UI требует независимого DOM/accessibility readback и успеха всех сценариев. Security использует локальные правила и allowlist мест findings. Ошибка, неполный ответ и недоступность не могут стать PASS. `disabled` сохраняет `passed:null`.
- Привязать квитанции схемы 1 к head/config/pins и SHA-256 evidence; проверять их перед review/delivery, включая прямую доставку. Сырые traces и секреты остаются вне Git; запись по умолчанию выключена. Старый audit schema 1 не меняется.
- `buildTaskContext(run,task)` передаёт до 16000 символов задачи, scope, acceptance, interfaces, constraints, кратких прямых зависимостей и релевантных ссылок. Политика навыков передаётся отдельно. Полная история, `analysis.standards` и сырые research bodies исключены.
- `progress.md` атомарно строится из авторитетного SQLite-состояния в артефактах запуска, не более 64 KiB, без сырых промптов и секретов. Resume восстанавливает сводку и не повторяет завершённые узлы. Бюджет ремонта по умолчанию пять, явный меньший сохраняется; исчерпание записывает controller assessment и блокирует автоматические повторы. Явный `--retry-failed` открывает новый цикл с прежней историей.
- В desktop host координатор использует доступные app tools для реальной работы в понятно названных видимых чатах; сохраняет диспетчер активным и архивирует только собственные завершённые рабочие чаты. CLI-native sessions сами не становятся видимыми чатами; универсальный desktop backend этим решением не объявляется.

## Альтернативы

| Вариант | Причина отказа |
| --- | --- |
| Выдать всем workers сервисные ключи и личный браузер | Нарушает границы процесса, приватности и владения ресурсами |
| Заменить реальный adapter fixture-ответом, MCP-каталогом или verdict модели | Не подтверждает выполнение upstream-инструмента и состояние приложения |
| Повторно доверять одному `passed:true` | Позволяет доставить другую ревизию, config или повреждённое evidence |
| Устанавливать инструменты глобально или при импорте | Ломает воспроизводимость, пользовательские окружения и офлайн CI |
| Вкладывать полную историю в каждую задачу | Увеличивает контекст, переносит нерелевантные данные и приватный вывод |
| Постоянно удалять чаты или править базы клиента | Не соответствует поддерживаемому archive/cleanup и мешает восстановлению |

## Последствия и проверка

Включённые gates добавляют зависимости окружения и могут блокировать доставку; старые проекты по умолчанию получают disabled. Managed install/doctor — доказательство локальной установки, UI-квитанция — конкретного сценария, package smoke — артефакта. Ни один из этих уровней сам по себе не подтверждает deployment.

Две регрессии воспроизведены красными на старом срезе documenter: `Engine counts changed contents of the same uncommitted file as progress through the fifth node round` и `UI rejects bridge results above the configured step budget despite passing independent observations`. Затем координатор подтвердил 25 целевых PASS в integration и дополнительный `Engine counts changing contents of a new untracked file as progress within the explicit budget`. Проверка исходников integration `e85240c53a5059e0e19212ced2f841fea58441fc` подтверждает fingerprint содержимого и передачу normalized config в обе проверки UI-результата. Это не утверждение зелёного общего check на старом дереве documenter. [Точные проверки и реальные квитанции](../archive/VALIDATION.md#интеграция-ui-security-и-контекста), [публичная конфигурация и pins](../UI-TOOLS.md).

Проверенный урок: exploratory QA может найти дефект самой fixture, даже когда инструмент корректно прошёл форму. Первый общий live run выявил пустое имя; required+trim исправлены в `0605cec`, Vibetest перепроверен в `1ad830e`. Отрицательный результат сохраняется, исправляется приложение и повторяется сценарий; удалять находку для зелёного отчёта нельзя. Место и история квитанций записаны в VALIDATION, приватные traces не копируются в репозиторий.
