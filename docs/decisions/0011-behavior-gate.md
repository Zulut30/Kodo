# ADR-0011: behaviour gate — защита тестов, оракулы поведения и политика по типу изменения

Статус: решение для MVP09. Приёмку этапа фиксирует [отчёт](../kodo-roadmap/phase-09.md), не этот ADR.

## Контекст

До этапа 09 итоговый commit проверяли команды проекта, три необязательных gate и независимый read-only reviewer. Ревью не могло отменить упавшую проверку, но ничто не мешало реализации сделать проверки зелёными, удалив или пропустив тест, а оценка «поведение верное» оставалась за моделью. Запрет «не ослабляй проверки» существовал только как текст prompt.

## Решение и альтернативы

| Выбор | Альтернатива и причина отказа | Последствие |
| --- | --- | --- |
| Отдельный шаг между локальными проверками и остальными gates, сбой которого идёт в существующий цикл ремонта | Четвёртый gate в общем кортеже: потребовал бы обнулять поле в семи местах и менять `delivery`/Director | Ревью не запускается при сбое; ремонт, `no_progress` и `repairRounds` работают без изменений |
| Защита тестов включена по умолчанию и отклоняет удаление и выключение существующих кейсов | Opt-in: защита не работала бы почти нигде. Отклонять по числу утверждений: вынос утверждений в helper и замена двух `assert.ok` одним `deepEqual` — обычная работа | Утверждения — только предупреждение |
| Явное разрешение на удаление конкретных тестов (`testRemovalAllowed`) | Единственный выход `testProtection: false`: отключал всю защиту ради одного устаревшего теста | Разрешение узкое и видно в квитанции |
| Сверка тест-кейсов по именам после разбора, который отличает код от строк и комментариев | Подсчёт маркеров регулярными выражениями: две версии подряд давали и ложные блокировки (`{ skip: … }` в данных, `'src/**'` в строке, перенос кейсов), и лазейку (удалённый тест прикрывался добавленным). Полный AST каждого языка: большой объём ради MVP. Модель-судья: то самое доверие, которое убираем | Удаление нельзя прикрыть новыми тестами; перенос и разделение проходят; переименование кейса отклоняется как удаление; семантическое ослабление не видно |
| Находка, которую не может исправить ремонт, останавливает запуск сразу | Отправлять в ремонт любую находку: выключенный gate сжигал раунды впустую | Код `behavior_blocked`, сессии не расходуются |
| Оракул — команда проекта, а не встроенный в Kodo набор | Реестр оракулов по доменам в Kodo: Kodo не знает домен проекта | Проект сам задаёт эталон; Kodo гарантирует запуск, неизменность и приоритет над ревью |
| Защищённые пути оракула обязаны совпадать с базой | Доверять плану: исполнитель с областью записи `oracle/**` мог бы переписать судью | Изменённый оракул не запускается и даёт сбой |
| Незавершившийся оракул — сбой | Считать таймаут пропуском: недоступность инструмента превращалась бы в PASS | Пробел доступности виден как сбой, а не скрыт |
| Политика выводится из изменённых путей; пробел по умолчанию только записывается | Блокировать при любом выключенном gate: проекты без gates не смогли бы работать | `strictGates: true` делает пробел сбоем; `disabled` никогда не PASS |
| Базовый прогон opt-in и только помечает сбой | Игнорировать старые сбои: внесённая регрессия могла бы спрятаться за старой ошибкой | Старая ошибка остаётся сбоем; ремонт знает, внесена ли она изменением |
| Блок `verification` только проверяется при чтении конфигурации | Записывать значения по умолчанию в `run.config`: изменил бы форму сохранённых конфигураций | Значения по умолчанию применяются там, где блок читается |

## Границы

- Доставка по-прежнему требует ревью и включённые gates; квитанция behaviour gate в `delivery` отдельно не проверяется. Порядок шагов в Engine гарантирует, что ревью и доставка следуют только за пройденным шагом на том же head.
- Сравнение с базой идёт на уровне команды. Отдельные тесты не различаются.
- Оракул выполняется с окружением исполнителя без секретов провайдеров, как и локальные проверки.
- Политика знает только пути. Изменение поведения auth в файле с нейтральным именем она отнесёт к `code`.
- Project Director не сверяет квитанцию behaviour gate и не замечает изменение блока `verification` в конфигурации проекта между запусками.
- Файлы тестов больше 256 КБ не проверяются; квитанция перечисляет их в `unchecked`.

## Что отложено

Адаптер OpenCodeReview, Evolution Gate, property-based/fuzz и mutation-кампании, реестр SHA-256 всех замороженных oracle-тестов самого Kodo, доменные оракулы (UI, SQL, Hearthstone), сравнение на уровне отдельных тестов.
