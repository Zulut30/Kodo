# ADR-0012: сторож прогресса и запись текущего блокера

Статус: решение для MVP10. Приёмку этапа фиксирует [отчёт](../kodo-roadmap/phase-10.md), не этот ADR.

## Контекст

До этапа 10 запуск останавливали два правила: одинаковая сигнатура сбоя на том же commit и исчерпанный `repairRounds`. Исполнитель, который каждый раунд выдаёт новый текст и новый commit, проходил первое правило и расходовал весь бюджет. Причина остановки хранилась в `run.error`, которое очищалось только при успехе: после `resume` сводка показывала ошибку прошлой попытки как текущий блокер.

## Решение и альтернативы

| Выбор | Альтернатива и причина отказа | Последствие |
| --- | --- | --- |
| Прогресс — только изменение принятого критерия (узел, команда проверки, gate, находки) | Считать прогрессом изменение head или текста ошибки: именно это и имитирует топтание на месте | Сторож не наблюдает commit, сессии и вывод вовсе |
| Порог `stalledRounds` выключен по умолчанию | Включить со значением 2: запуск, который за три раунда чинит по одному тесту внутри одной команды, останавливался бы раньше бюджета | Поведение без настройки прежнее; порог задаёт проект |
| Состояние сторожа — данные в Run, шаг идемпотентен по ключу раунда | Счётчик в памяти: терялся бы при перезапуске; отдельная таблица: вторая запись о том же | Перезапуск и пауза по квоте не сбрасывают и не удваивают счёт |
| Отдельное поле `run.blocker` с текущим блокером и историей | Очищать `run.error` при `resume`: на него опираются сохранённые запуски, Director и тесты | `run.error` не меняется; текущим считается только `run.blocker.current` |
| Гипотезы выводятся из записанных фактов по таблице | Просить модель объяснить сбой: недетерминированно и стоит сессию | Гипотез немного, и они не вердикт; зато воспроизводимы |
| Косметическим считается только отсутствие изменений или различие в пустых строках в обычных JS/TS и Python без шаблонных, многострочных и продолженных строк; только по настройке | Сравнивать diff без пробелов и по началу строки: первая версия отклоняла исправление отступа в Python и строки `#count = 1`. Таблица синтаксисов по расширению с блочными комментариями: вторая версия принимала за комментарий `* { … }` в CSS, оператор в начале строки, текст внутри шаблонной строки. Строчные комментарии с перечнем директив: третья версия принимала за косметику `// nosemgrep`, `# pyright:`, `//= require` и зависимости PEP 723, а перечень директив закрыть нельзя | Узел, который добавил только комментарии, не отклоняется: его оценивают проверки и ревью. Зато настоящая работа не отклоняется; вывод git читается без редактирования секретов |
| У остановки без собственной области текст входит в тождество блокера | Тождество только по коду, области и commit: разные необработанные ошибки склеивались в один блокер со старым текстом | Сводка показывает последний текст; разные ошибки уровня запуска — разные блокеры |
| Прогресс считается относительно лучшего достигнутого состояния | Сравнивать с предыдущим раундом: «сломал — починил» засчитывалось как прогресс | Возврат к уже достигнутому состоянию прогрессом не является |
| Блокер определяется причиной, областью и commit; область и причину несёт ошибка остановки | Сигнатура по тексту ошибки и область из последней оценки координатора: повторный `resume` плодил копии, а при двух остановившихся узлах область была чужой | Повторная остановка увеличивает счётчик; блокер относится к узлу, чья ошибка остановила запуск |
| Сторож только останавливает | Автоматически менять подход, модель или план: расход без решения пользователя | Следующий шаг выбирает человек или явный `--retry-failed` |

## Границы

- Сравнение идёт на уровне команды проверки. Прогресс внутри одной команды (меньше упавших тестов) сторож не видит.
- На уровне узла плана действуют прежние правила (`repairRounds` и сигнатура сбоя с отпечатком рабочего дерева); порог `stalledRounds` относится к раундам проверки запуска.
- Косметика распознаётся только как отсутствие изменений или различие в пустых строках в обычных JS/TS и Python. Правки комментариев, другие языки и любые другие пробелы не судятся и считаются настоящей работой.
- Блокер записывается для состояний `blocked` и `waiting_limits`. Отмена блокером не считается.
