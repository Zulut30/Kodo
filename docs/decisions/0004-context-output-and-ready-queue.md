# ADR-0004: Компактный контекст, локальный вывод и непрерывная очередь

**Дата:** 2026-11-03. **Статус:** решение задано контрактом run `16877cd8-f73a-43de-ab00-5c098211c20e` и отражено в исходниках A/B/C/D на базе `6a21156d8da652d7b5437e5ced13e2b1bf775854`. Целевые D/E результаты получены отдельно; общий check/CI, финальное review, опубликованный пакет и deployment на этапе F не подтверждены. Это решение уточняет передачу контекста из [ADR-0002](0002-ui-security-and-progress.md) и сохраняет режимы/методологию [ADR-0003](0003-execution-modes-and-benchmarks.md).

## Контекст

Ожидание всей группы задач задерживает готовый зависимый узел. Дублирование upstream-текстов, анализа, истории, полного diff и logs увеличивает начальный контекст. Простое усечение может потерять acceptance, диагностику или статус неуспеха; output-фильтр может сохранить exit code, скрыв причину. Подписочные клиенты не раскрывают общую квоту и точную стоимость задачи через размер промпта.

## Решение

1. Использовать событийную dependency-ready очередь вместо барьера группы. Engine сохраняет ownership состояния, worktree, routing, retries и merge. Интеграция последовательна; новый зависимый узел допускается после `integrated`, даже при работающем независимом соседе. Сохраняются run concurrency, subscription leases capacity 2, решения plan/Jev о parallel и запрет перекрывающихся scopes. На сбое новый допуск прекращается, начатая работа дожидается завершения; failed pending merge восстанавливается до других интеграций. Отмена не начинает новые merge. Completed recovery не вызывает worker заново.
2. Планировать небольшие связные module deliverables с interfaces и узкими scopes, только реальными dependencies и ранними scoped tests/docs. Не дробить tiny change искусственно и не добавлять вызов планировщика. Quick, explicit mode/model и меньшие бюджеты сохраняются; resume не повышает режим. Маршрутизация использует bounded snapshot готовых/активных peers и не переигрывает сохранённый serial-выбор.
3. Оставить все 13 applicability/provenance решений, полные применимые Kodo adapters и проверку каждого pinned resource. Upstream-тексты доступны по абсолютным read-only ссылкам вместо повторяемых excerpts. React/monorepo остаются условными. Registry сохраняет 33 компонента.
4. До compaction сохранять полный REDACTED snapshot вне Git в приватном content-addressed JSON с base/head. Компактные plan/review JSON сохраняют статусы, ссылки, commands/exits и явные потери. Head/hash проверяются до/после сессии и перед reuse полных check logs; повреждение даёт `evidence_integrity`, не расходуя code repair/research. Полные evidence доступны worker/reviewer по необходимости. Неизвестное/failed/skipped не превращаются в PASS.
5. Передавать mandatory node core без усечения. Для новых планов лимит сериализованного ядра — 12000 UTF-8 байт; превышение требует разбиения. Старые oversized contracts получают явную обязательную ссылку на полный файл. Необязательные сведения узла ограничены отдельно. До трёх verified lesson summaries допускаются только при успешных head-bound checks/review; полные lessons остаются в analysis evidence.
6. Добавить RTK OSS 1.1.0 десятым managed tool через существующие installer/receipt/integrity границы, с pinned Windows x64/Linux x64 assets. Готовый RTK — явная опция для поддерживаемого человекочитаемого вывода в native-сессии. Private DB/recall0/tee0/telemetry-off и worker PATH изолированы от global RTK 0.50.0; HOME/auth не меняются. Разрешение инструмента выполняется после lease и повторяется для следующей сессии. Missing/unsupported использует исходные команды без per-session install.
7. Оставить JSON/porcelain/NUL/protocol, Node/TAP, проверки координатора, CI, gates и delivery сырыми. При потере ошибок повторить исходную команду и сохранить полную redacted диагностику. Не добавлять hooks, config-save, API routing/rtk-proxy или замену пользовательских binaries. GPT/Claude исполняются только подписочными клиентами; host app не наследует worker env автоматически.
8. Записывать фактические финальные redacted prompt bytes по попытке и raw/sent bytes компактируемой части; неизвестное сохранять `null` с полнотой. Native usage/cache semantics не менять. Отдельные локальные size deltas не выдавать за общее ускорение, quota, billed tokens или USD. Матрица моделей остаётся отложенной. Native auth/env probe без inference — отдельный уровень доказательств.

## Альтернативы

| Вариант | Причина отказа |
| --- | --- |
| Ждать всех независимых задач перед следующим слоем | Задерживает уже готовый downstream без зависимости от медленного соседа |
| Принудительный parallel поверх решения Jev | Нарушает ограничения routing, scopes и выбранных бюджетов |
| Срезать весь prompt по символам | Теряет late acceptance, команды, Unicode и полноту evidence |
| Скрыть источники и убрать все prior lessons | Лишает reviewer деталей и проверенных полезных знаний проекта |
| Кэшировать policy/tool integrity навсегда | Не обнаруживает подмену ресурсов между сессиями |
| Пропускать любой вывод через RTK | Повреждает протоколы и actionable Node/TAP diagnostics |
| Глобальная установка/hooks или RTK proxy | Меняет пользовательское окружение и границы подписочных клиентов |
| Превратить bytes/4 или проценты частей в квоту подписки | Не измеряет полную native-сессию, cache/tokenization и лимиты аккаунта |

## Последствия и проверка

Контекст может быть меньше, но модель должна прочитать полные файлы по необходимости. Метаданные способны увеличить tiny input; budget failures явны. Очередь улучшает допуск готовой работы, но не гарантирует wall-time ускорение при serial routing, лимите подписки или интеграции. Приватные evidence требуют защищённого хранения и проверки неизменности; они не заменяют изоляцию недоверенного кода от того же пользователя ОС.

В локальных фиксированных входах policy сократилась на 51,74–59,36%, inline plan/review evidence — на 89,15%/91,79%, успешный RTK Git log — на 63,65%. Это разные части данных, их проценты не складываются. Node/TAP negative fixture потеряла sentinel и исключена из принятой экономии. Полные значения, provenance, проверенные уроки и пределы native auth/env квитанции — в [EFFICIENCY](../EFFICIENCY.md), команды и независимые сценарии — в [VALIDATION](../VALIDATION.md#контекст-очередь-и-rtk).

Проверенные уроки: compact summary должна соответствовать одному сохранённому snapshot; content-addressed имя требует повторной проверки bytes/head; tool integrity следует проверять после lease; отрицательная диагностика важнее одного exit code; routing-вопрос должен совпадать с ready frontier; Windows pipe для artifact paths требует явного UTF-8. Эти контракты имеют целевые регрессии D/E. Финальный интегрированный check, свежие gates/review, CI и проверка конкретного release остаются у координатора. Видимые scoped чаты и их архивирование поддерживаются текущим частным host-adapter, не универсальным desktop backend CLI.

Уточнение по проверке: полная буквальная `${variable.property}` в примере авторизации сохраняется; реальные и известные значения скрываются до любого сокращения. Это применяется общей границей ко всем контрактам/evidence/промптам. Подготовка приватного каталога объединяется только внутри ограниченного пакета записей, до запуска worker; следующая партия заново применяет защиту. Каталог проверяется на замену, writer после закрытия партии недействителен. Нагрузочные тесты отделяют deadlock guard от причинного требования допуска downstream.

Дополнительный урок независимого ревью: очистка всего готового промпта может повредить escape-байты сериализованного JSON. Структурированные поля очищаются до упаковки; закрытый внутренний контракт связывает неизменяемые evidence и metrics по identity. Обычный текст очищается отдельно. Поддельные контракты/metrics отвергаются; тесты проверяют JSON.parse и точный отправленный размер на границе провайдера.
