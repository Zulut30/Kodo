# Статистика registry

`kodo registry stats` показывает сводку по всем компонентам поставляемого с CLI каталога `registry.json`. Команда читает локальный каталог без установки компонентов и обращения к внешним сервисам. Она не подсчитывает компоненты, установленные в целевом проекте.

## Запуск

После установки CLI:

```powershell
kodo registry stats
kodo registry stats --json
```

Эквивалентный запуск из корня репозитория с Node.js 24 или новее:

```powershell
node cli/index.mjs registry stats
node cli/index.mjs registry stats --json
```

Без `--json` команда выводит таблицу для чтения в терминале. С `--json` в стандартный вывод (`stdout`) записывается JSON-объект с отступами, без заголовка таблицы. При успешном выполнении код завершения — `0`, стандартный поток ошибок (`stderr`) пуст.

Синтаксис `kodo registry stats [--json]` приведён в общей справке:

```powershell
kodo --help
node cli/index.mjs --help
```

`kodo registry stats --help` (или `node cli/index.mjs registry stats --help`) также показывает общую справку Kodo.

## Контракт JSON и смысл счётчиков

Объект содержит четыре поля:

| Поле | Тип | Значение |
| --- | --- | --- |
| `version` | Строка | **Версия registry** из поля `version` файла `registry.json`. Это не версия CLI-пакета или отдельного компонента, даже если значения совпадают. |
| `total` | Целое неотрицательное число | Число всех записей в `components`, независимо от типа и наличия зависимостей. |
| `byType` | Объект | Число компонентов каждого из пяти типов: `skill`, `agent`, `pipeline`, `mcp`, `preset`. Все пять ключей присутствуют; для типа без компонентов значение равно `0`. Сумма значений равна `total`. |
| `dependencies` | Целое неотрицательное число | Общее число прямых ссылок во всех массивах `requires` компонентов registry. |

`dependencies` считает ссылки с повторным учётом одной зависимости у разных компонентов. Если два компонента указывают один и тот же навык в своих `requires`, это две ссылки. Транзитивные зависимости дополнительно не разворачиваются: для цепочки `A → B → C` учитываются две записанные прямые ссылки. Пустой массив `requires` добавляет `0`. Это не число уникальных зависимостей и не размер плана установки.

Пример вывода `kodo registry stats --json` для поставляемого registry версии `0.2.0`, включая 13 стандартных инженерных навыков Kodo. Версия и числа отражают этот каталог и могут измениться при его обновлении; они не являются постоянными значениями контракта.

```json
{
  "version": "0.2.0",
  "total": 33,
  "byType": {
    "skill": 18,
    "agent": 5,
    "pipeline": 4,
    "mcp": 3,
    "preset": 3
  },
  "dependencies": 51
}
```

## Таблица

Пример вывода `kodo registry stats` для того же поставляемого registry:

```text
Показатель           | Значение
Версия registry      | 0.2.0
Всего компонентов    | 33
skill                | 18
agent                | 5
pipeline             | 4
mcp                  | 3
preset               | 3
Ссылок requires      | 51
```

Строки таблицы передают те же данные: версию registry, общее число компонентов, пять счётчиков по типам и общее число ссылок `requires`. Для обработки скриптами используй `--json`.

При обновлении состава каталога сверяй оба примера с выводом команды и обновляй проверенные значения и строки `list` в `tests/registry-stats.test.mjs`: добавление компонентов или ссылок меняет счётчики даже без изменения версии registry.

## Аргументы и ошибки

Команда принимает ровно подкоманду `stats`, необязательный флаг `--json` без значения и `--help` для общей справки. Дополнительные позиционные аргументы и параметры фильтрации или установки не поддерживаются.

В примерах ниже показан полный текст сообщения в `stderr`. При этих ошибках код завершения — `1`, `stdout` пуст, в том числе при использовании `--json`: ошибка не преобразуется в JSON.

| Вызов | Сообщение |
| --- | --- |
| `kodo registry` | `Ошибка: Использование: kodo registry stats [--json]` |
| `kodo registry unknown` | `Ошибка: Использование: kodo registry stats [--json]` |
| `kodo registry stats extra` | `Ошибка: Использование: kodo registry stats [--json]` |
| `kodo registry stats --unknown` | `Ошибка: Неизвестный параметр: --unknown` |
| `kodo registry stats --target x` | `Ошибка: Параметр target неприменим к registry` |
| `kodo registry stats --target` | `Ошибка: Требуется значение --target` |
| `kodo registry stats --client codex` | `Ошибка: Параметр clients неприменим к registry` |
| `kodo registry stats --preset nextjs` | `Ошибка: Параметр preset неприменим к registry` |
| `kodo registry stats --dry-run` | `Ошибка: Параметр dry-run неприменим к registry` |
| `kodo registry stats --json=true` | `Ошибка: Неизвестный параметр: --json=true` |
| `kodo registry stats --json true` | `Ошибка: Использование: kodo registry stats [--json]` |

Для воспроизведения из исходников замени `kodo` на `node cli/index.mjs`. Например:

```powershell
node cli/index.mjs registry stats extra
```

`registry stats` — отдельная команда сводки. Она не меняет синтаксис и поведение существующих команд, включая `list`: `kodo list [skill|agent|pipeline|mcp|preset] [--json]` по-прежнему выводит список компонентов, а не статистику.
