## Соответствие приёмке

| Запуск должен остановиться при | Чем подтверждено |
| --- | --- |
| Корректной компиляции, но неправильном поведении | Реализация `blobId` без заголовка Git загружается и проходит проверку загрузки, оракул сверяет её с установленным `git hash-object` и останавливает; после одного ремонта запуск успешен |
| Удалении или выключении теста | Удалённый и пропущенный существующий тест дают `test_deleted` и `test_skipped`; запуск `blocked`, ревью не вызывается. Кейсы сверяются по именам: удаление нельзя прикрыть новыми тестами, закомментированный тест и переименование из каталога тестов отклоняются. Семантическое ослабление защита не видит |
| Ошибке в зависимом модуле | Проверка использует потребителя изменённого модуля; при базовом прогоне сбой помечен `regression`, старая ошибка — `pre_existing` и не игнорируется |
| Stale/current-head mismatch | Квитанция не принимается для другого head, другой базы и изменённой конфигурации |
| Липовом отчёте ревью | Reviewer-заглушка всегда отвечает PASS; при красном оракуле ревью не запускается, `run.review` пуст, доставка не вызывается |
| Проваленном UI gate | Существующие `tests/verification-gates.test.mjs`: порядок шагов не менялся, behaviour gate стоит перед ними |

Отдельно показаны: быстрый путь для правки стилей с записанным пробелом UI gate (и остановка при `strictGates`) и сверка с Git как сложный conformance-путь. Rust-пути нет.

## Независимое ревью

Первая версия прошла read-only ревью отдельным агентом. Вердикт — FAIL: два major. Обход через конфигурацию, доставка в обход шага и утечки секретов проверены и не найдены. Все замечания исправлены, кроме перечисленных ниже как ограничения.

| Замечание | Исправление |
| --- | --- |
| major: защита по умолчанию блокировала честную работу (`regex.test(` считался кейсом, учёт по одному файлу, снятие `describe`, вынос утверждений) и выхода, кроме отключения всей защиты, не было | Кейсы считаются по всем изменённым тестам; `describe` и `regex.test` не кейсы; утверждения — предупреждение; явное разрешение `testRemovalAllowed` |
| major: частые способы выключить тест не ловились, а документы обещали обратное | Комментарии удаляются перед подсчётом; добавлены формы `skip:`, `t.skip()`, `todo`, `@unittest.skip`, `pytest.skip()`, `#[ignore = …]`; переименование из каталога тестов — удаление. Документы перечисляют, чего защита не видит |
| Файл больше лимита вывода ронял шаг; квадратичное выражение на длинной строке; тихий пропуск непрочитанного | Чтение не бросает исключений; выражение линейное; файлы больше 256 КБ не проверяются и попадают в `unchecked` |
| Неустранимые находки уходили в ремонт | `required_gate_disabled` останавливает запуск сразу (`behavior_blocked`) |
| Базовый прогон устаревал после синхронизации базы; незавершённая команда базы помечалась как старая ошибка | Пометки даются только для текущей базы; незавершённая команда — `no_baseline` |
| Чистота дерева проверялась один раз после всех оракулов; сбой запуска оракула не оставлял evidence | Проверка после каждого оракула (`oracle_dirty_worktree`); evidence сохраняется и при сбое |
| `AUTHORS.md` и `src/author.ts` считались security; Dockerfile и terraform — code; скрипт в `docs/` — content | Классификация по целым словам и расширениям |

Не исправлено, записано как ограничение: Project Director не сверяет квитанцию и блок `verification`; при `strictGates` релизный commit версии требует security gate; переименование теста внутри каталога тестов в имя, которое runner не подхватывает, не распознаётся; переименование кейса отклоняется как удаление; подтесты и параметризованные кейсы с нелитеральным именем не сверяются.

Второе ревью снова дало FAIL: три major, два из них внесены исправлениями первого круга.

| Замечание второго ревью | Исправление |

| major: ключ `skip:`/`todo:` в данных теста и новый тест с условным пропуском давали ложный `test_skipped` | Пропуск ищется только в объекте опций сразу после имени кейса и только для кейса, который существовал на базе |
| major: `/*` внутри строки (`'src/**'`) принимался за начало комментария: часть тестов выпадала из счёта | Разбор отличает код от строк, шаблонных строк, регулярных выражений и комментариев |
| major: удалённый тест прикрывался любыми добавленными кейсами | Сверка по именам кейсов вместо суммы |
| Разрешение ломало допуск на перенос и снимало также пропуски | Разрешение относится только к удалению и к пути файла на базе |

Разборщик дополнительно проверен на 98 файлах тестов самого Kodo вне набора тестов: безобидная правка каждого файла не даёт ни одной находки, удаление одного кейса находит именно его. Эта проверка нашла ошибку разбора шаблонных строк с `${…}`; она исправлена и закреплена тестом.

Третье ревью: FAIL, один major. Ложных блокировок обычной работы оно не нашло.

| Замечание третьего ревью | Исправление |
| --- | --- |
| major: пропуск на уровне группы не давал находки (`describe.skip`, `xdescribe`, опция `skip` у `describe`, `describe.only` у соседней группы, `test.describe.skip`, декоратор над классом Python, `pytestmark`) | Кейс считается выключенным, если пропуск стоит на нём или на окружающей группе, классе, модуле. `.only`, добавленный в файл с существующими кейсами, отклоняется |

| Неточности документации | Исправлены пример квитанции и примеры путей; перечислены файлы тестов, которые не узнаются по пути |

До исправления падал 21 новый подтест. Тест линейности на прежнем коде не запускался. Оставшиеся границы перечислены в `docs/VERIFICATION.md`: кейсы с именем-выражением сверяются только числом, часть форм пропуска не распознаётся, разбор JS ошибается на регулярном выражении сразу после `)`.

Четвёртое ревью: **PASS**, замечания minor. Исправлены четыре ложные блокировки и одна лазейка:

- `/` после `<` больше не читается как регулярное выражение: новая пропущенная группа с JSX (`</App>`) выключала для разбора остаток файла;
- условный пропуск Playwright в теле теста (`test.skip(условие, 'причина')`) считался кейсом с именем-выражением, и его снятие давало `tests_removed`. Теперь это вызов пропуска: снятие проходит, добавление в существующий тест отклоняется;
- `@Disabled` на новом методе Java/Kotlin выключал соседние тесты: слово `class` в тексте аннотации принималось за класс, а аннотация искалась в окне символов перед `@Test`;
- `pytestmark` списком на нескольких строках, с аннотацией типа и внутри класса не давал находки.

Остальные замечания записаны как границы в `docs/VERIFICATION.md`.

Ревью этих исправлений: FAIL по одной причине. Новое выражение для `@Disabled` над классом было квадратичным: 47 секунд на враждебном входе в 256 КБ. Повторения ограничены, вход добавлен в тест линейности. Заодно исправлено: строки и строчные комментарии в Java и Kotlin не считаются кодом (причина пропуска с `;`, скобками или словом `class` больше не скрывает аннотацию); `} />` в JSX не открывает регулярное выражение; вызов пропуска без имени (`test.fixme()`, `test.skip(!условие, …)`) считается вызовом пропуска; `pytestmark` в теле класса покрывает весь класс, а одноимённая переменная в методе — ничего.

Следующее ревью: FAIL по той же причине в соседнем месте. Замена строковых литералов Java и Kotlin регулярным выражением была квадратичной: 44 секунды на входе из пар `"\`. Вместо выражения — один проход по тексту, как для JS/TS: строки, символьные литералы, текстовые блоки и комментарии (в том числе блочные) кодом не считаются. Вход добавлен в тест линейности. Заодно: заголовок класса Python на нескольких строках не сбивает определение тела класса; блочный комментарий и модификатор между `@Disabled` и `@Test` не скрывают аннотацию.

Автоматическое ревью Codex в PR: при одинаковых именах кейсов в двух изменённых файлах удаление приписывалось не тому файлу и могло пройти по разрешению, выданному для другого пути. Теперь кейс сначала ищется в своём файле, и только недостающее сверяется с переносами; добавлен тест.

## Изменённое существующее поведение

- В каждом раунде проверки появился шаг behaviour gate. Без блока `verification` он выполняет только защиту тестов: две команды `git diff`, до двух `git show` на каждый изменённый файл тестов и проверка чистоты рабочего дерева.
- Реализация, которая удаляет или явно пропускает существующие тесты, теперь блокируется. Раньше это запрещал только текст prompt.
- В Run появилось поле `behavior`; при `baseline: true` — поля `baseline` и `checks.comparison`.

## Что не сделано

- **Адаптер OpenCodeReview** (scope ④): инструмента и его закреплённой версии в репозитории нет.
- **Evolution Gate**, property-based/fuzz-тесты и выборочное mutation-тестирование.
- **Доменные оракулы** для UI (Playwright), SQL и Hearthstone. Механизм оракулов общий; готовых оракулов для этих доменов нет.
- **Сложный Rust conformance path**: показан только Git-оракул на JS-fixture.
- **Проверка квитанции в `delivery` и Project Director**: приоритет над ревью обеспечивает порядок шагов Engine.
- **Реестр SHA-256 замороженных oracle-тестов самого Kodo**.
- **Анализ Gemini и оценка Jev** перед этапом не выполнялись: в этой среде нет настроенного Kodo runtime с провайдерами.

## Ограничения

- Защита тестов — эвристика по маркерам. Замену утверждения более слабым она не видит.
- Сравнение с базой работает на уровне команды и удваивает время проверок, поэтому выключено по умолчанию.
- Политика по типу изменения знает только пути.
- Все свидетельства этапа — offline.
