Статус на 2026-11-10: **реализация завершена, кандидат на приёмку.** Ветка `kodo/09-behavior-gate` поверх этапа 08. Проверки замороженного head, ревью и CI перечислены в описании PR этапа.

## Соответствие приёмке

| Запуск должен остановиться при | Чем подтверждено |
| --- | --- |
| Корректной компиляции, но неправильном поведении | Реализация `blobId` без заголовка Git загружается и проходит проверку загрузки, оракул сверяет её с установленным `git hash-object` и останавливает; после одного ремонта запуск успешен |
| Удалении или ослаблении теста | Удалённый и пропущенный существующий тест дают `test_deleted` и `test_skipped`; запуск `blocked`, ревью не вызывается |
| Ошибке в зависимом модуле | Проверка использует потребителя изменённого модуля; при базовом прогоне сбой помечен `regression`, старая ошибка — `pre_existing` и не игнорируется |
| Stale/current-head mismatch | Квитанция не принимается для другого head, другой базы и изменённой конфигурации |
| Липовом отчёте ревью | Reviewer-заглушка всегда отвечает PASS; при красном оракуле ревью не запускается, `run.review` пуст, доставка не вызывается |
| Проваленном UI gate | Существующие `tests/verification-gates.test.mjs`: порядок шагов не менялся, behaviour gate стоит перед ними |

Отдельно показаны: быстрый путь для правки стилей с записанным пробелом UI gate (и остановка при `strictGates`) и сверка с Git как сложный conformance-путь. Rust-пути нет.

## Изменённое существующее поведение

- В каждом раунде проверки появился шаг behaviour gate. Без блока `verification` он выполняет только защиту тестов: одна команда `git diff` и чтение изменённых файлов тестов.
- Реализация, которая удаляет, пропускает или вычёркивает существующие тесты, теперь блокируется. Раньше это запрещал только текст prompt.
- В Run появилось поле `behavior`; при `baseline: true` — поля `baseline` и `checks.comparison`.

## Что не сделано

- **Адаптер OpenCodeReview** (scope ④): инструмента и его закреплённой версии в репозитории нет.
- **Evolution Gate**, property-based/fuzz-тесты и выборочное mutation-тестирование.
- **Доменные оракулы** для UI (Playwright), SQL и Hearthstone. Механизм оракулов общий; готовых оракулов для этих доменов нет.
- **Сложный Rust conformance path**: показан только Git-оракул на JS-fixture.
- **Проверка квитанции в `delivery` и Project Director**: приоритет над ревью обеспечивает порядок шагов Engine.
- **Реестр SHA-256 замороженных oracle-тестов самого Kodo**.
- **Анализ Gemini и оценка Jev** перед этапом не выполнялись: в этой среде нет настроенного Kodo runtime с провайдерами.

## Ограничения

- Защита тестов — эвристика по маркерам. Замену утверждения более слабым она не видит.
- Сравнение с базой работает на уровне команды и удваивает время проверок, поэтому выключено по умолчанию.
- Политика по типу изменения знает только пути.
- Все свидетельства этапа — offline.
