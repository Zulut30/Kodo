## Видение пользователя

Фабрика быстро создаёт большие проекты, сама создаёт и убирает воркер-сессии и распределяет между ними работу. Небольшая задача не должна затягиваться. Работа через T3 Code должна идти без ручных обходов.

## Решения пользователя (2026-11-23)

1. Быстрый путь без ключа Jev: стили и 1–3 небольших отслеживаемых файла кода.
2. Доказанно маленькая задача — 2 нативные сессии (реализация и независимое ревью); план строится локально.
3. Граница [ADR-0015](../decisions/0015-t3-pull-host.md) сохраняется: Kodo CLI не вызывает T3. Главный чат архивирует каждый воркер-чат сразу после итога его задачи.
4. Объём: реализация, push, выпуск v1.0.1 и обновление глобального `kodo`.

## Замер скорости

1. Локальный замер накладных расходов Kodo с мгновенным подменённым провайдером, реальными Git, SQLite и ACL — квота не тратится.
2. Парный прогон на одной модели (`benchmark run --models <одна> --repeats 1`) — только по отдельному слову пользователя: он тратит квоту подписки. В отчёте раздельно `wallMs`, `metrics.durationMs`, `firstEventMs`, число сессий и корректность.

## Не делаем

API-обход для GPT/Claude; отключение проверок, behaviour gate и независимого ревью ради скорости; правки баз T3 и вызовы T3 из CLI; правки замороженных `tests/*-oracle.test.mjs`, `tests/*-acceptance.test.mjs`, `migrationSql`, `CI_COMMAND_TIMEOUT_MS`; idle-таймаут сессии; полную матрицу бенчмарка; Orca, `--providers both`, TokenEconomizer.

### Найдено живой проверкой и исправлено после выпуска

- `bootstrap --prepare --client` отклонялся (`project_arguments`), поэтому шаблон `kodo.config.json` всегда получал `codex`. Исправлено в PR квитанций; войдёт в следующий выпуск. Обход в 1.0.1: задать `client` в `kodo.config.json` вручную (так и предписывает навык).
- npm с `allow-remote=false` отказывает в установке по URL (`EALLOWREMOTE`); в README описана установка скачанного архива.

### Не сделано и ограничения

- Парный бенчмарк на реальных подписках не запускался: он тратит квоту, только по отдельному слову пользователя.
- Остановка группы процессов на POSIX проверена кодом и CI Ubuntu, не локально; Windows Job Object не используется (ADR-0016).
- Конфликт метаданных выпуска (`package.json`) в быстром пути проверяется по файлу целиком (ADR-0016).
- `knowledge-refresh`: исторический сбой не воспроизведён, причина не установлена.

### Уроки

- Модели Gemini через Antigravity завершают ход на долгих командах — для них статическое ревью или короткие команды.
- Codex astra — самый строгий ревьюер: нашёл блокирующую инъекцию путей в командах брифа и дыры в правах записи быстрого пути.
- Права записи быстрого пути нельзя выводить эвристикой из текста задачи: только однозначно названные цели, неоднозначность — обычный маршрут.
- Фиксированный предел одной команды CI выдерживается выносом тяжёлых сквозных наборов в отдельные шаги, а не перестановкой порядка.
