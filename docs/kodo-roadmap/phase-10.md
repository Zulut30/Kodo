## Соответствие приёмке

| Требование | Чем подтверждено |
| --- | --- |
| Повторяющийся анализ без изменения успешности останавливается в заданном бюджете | Проверка каждый раунд падает с новым текстом, ремонт каждый раз добавляет комментарий и новый commit. При `stalledRounds: 2` запуск остановлен после двух ремонтов из бюджета пяти; без порога решает прежний бюджет |
| Сохранённое состояние позволяет диагностировать причину | `run.blocker.current`: код `no_verified_progress`, область `verification`, гипотеза, хэш вывода упавшей проверки, commit; те же сведения в `progress.md` |
| Порог и бюджет переживают restart | Ремонт прерван квотой, процесс заменён новым Engine на том же хранилище: счёт продолжен с 1, остановка на 2, ни один раунд не посчитан дважды |
| Независимая задача продолжает работать | Узел `stuck` не завершается и блокируется; независимый `free` завершён и интегрирован; блокер называет `stuck` |
| Только косметическое изменение не закрывает задачу | При `rejectCosmetic` узел developer с одним комментарием не засчитан, ревью не вызывается; узел documenter и запуск без настройки проходят |
| Восстановленная старая ошибка не стирает историю и не выдаётся за текущую | После `resume` прежний блокер в истории с исходом `resumed`; сводка пишет `Last error (previous attempt, not the current blocker)`; пауза по квоте после перезапуска — история, а не текущий блокер |
| Сторож не меняет код и доставку | Модуль не содержит записи в рабочее дерево, кроме `git add` перед сравнением diff, который и так выполняет commit узла; автоматических повторов нет |

## Независимое ревью

Первая версия прошла read-only ревью отдельным агентом. Вердикт — FAIL по одной причине: `rejectCosmetic` отклонял настоящие изменения. Путь с выключенным сторожем замечаний не получил. Все замечания исправлены.

| Замечание | Исправление |
| --- | --- |
| `rejectCosmetic` считал косметикой исправление отступа в Python, строки `#count = 1`, `*ptr = x;`, `--flag`, переименование, смену режима, новый пустой файл | Косметикой считается только заведомо косметическое изменение; синтаксис комментариев берётся по расширению; тест на 16 видов правок и 6 видов изменений файлов |
| «Сломал — починил» засчитывалось как прогресс | Сравнение с лучшим достигнутым состоянием |
| Счётчик повторов блокера был недостижим, каждый `resume` добавлял копию в историю | Блокер определяется причиной, областью и commit; повторная остановка продолжает ту же запись |
| При двух остановившихся узлах блокер получал область другого узла; evidence проверок прикладывалось к любой остановке | Область и причину несёт сама ошибка остановки; evidence — только для остановки на проверке |
| Отмена после `resume` выводилась как «прошлая попытка» | Отменённый запуск показывает `Stopped` |
| Строка `Watchdog` выводилась без настроенного порога | Выводится, только если порог задан или сработал |
| Документ не оговаривал, что часть диапазона порога ничего не меняет | Оговорено в руководстве |

## Изменённое существующее поведение

- В Run появились поля `blocker` и `watchdog`. `run.error` ведёт себя как раньше.
- `progress.md` для запусков с `run.blocker` печатает `Current blocker` или `Last error (previous attempt…)` вместо `Pending blocker`. Для запусков без этого поля строка прежняя.
- Без блока `watchdog` в конфигурации новых остановок нет.

## Что не сделано

- **Очередь `maintenance`, Maintenance PR и Health Budget.**
- **Эскалация** со сменой подхода, специалиста или плана: сторож только останавливает.
- **Адаптер ai-memory** (scope ③): сервиса и его закреплённой версии в репозитории нет.
- **Пороги по типу задачи** и прогресс внутри одной команды проверки.
- **Блокер в `kodo audit`**: он виден в `kodo status` и `progress.md`.
- **Анализ Gemini и оценка Jev** перед этапом не выполнялись: в этой среде нет настроенного Kodo runtime с провайдерами.

## Ограничения

- Порог `stalledRounds` считает раунды проверки запуска, а не попытки узла.
- Эффективный бюджет ремонтов ограничен профилем режима, поэтому при `standard` порог 2 совпадает с исчерпанием бюджета 3.
- Все свидетельства этапа — offline.
