## Соответствие приёмке

| Требование | Чем подтверждено |
| --- | --- |
| Повторяющийся анализ без изменения успешности останавливается в заданном бюджете | Проверка каждый раунд падает с новым текстом, ремонт каждый раз добавляет комментарий и новый commit. При `stalledRounds: 2` запуск остановлен после двух ремонтов из бюджета пяти; без порога решает прежний бюджет |
| Сохранённое состояние позволяет диагностировать причину | `run.blocker.current`: код `no_verified_progress`, область `verification`, гипотеза, хэш вывода упавшей проверки, commit; те же сведения в `progress.md` |
| Порог и бюджет переживают restart | Ремонт прерван квотой, процесс заменён новым Engine на том же хранилище: счёт продолжен с 1, остановка на 2, ни один раунд не посчитан дважды |
| Независимая задача продолжает работать | Узел `stuck` не завершается и блокируется; независимый `free` завершён и интегрирован; блокер называет `stuck` |
| Только косметическое изменение не закрывает задачу | Выполнено частично. Прогресс запуска считается только по результатам проверок, поэтому косметическая правка прогрессом не является и при заданном `stalledRounds` раунды не продлевает. При `rejectUnchanged` узел, который ничего не изменил, не засчитан, ревью не вызывается. Отдельного распознавания косметических правок нет: четыре версии такой проверки отклоняли настоящую работу (см. [WATCHDOG](../WATCHDOG.md)); такую правку оценивают проверки, behaviour gate и ревью |
| Восстановленная старая ошибка не стирает историю и не выдаётся за текущую | После `resume` прежний блокер в истории с исходом `resumed`; сводка пишет `Last error (previous attempt, not the current blocker)`; пауза по квоте после перезапуска — история, а не текущий блокер |
| Сторож не меняет код и доставку | Модуль не содержит записи в рабочее дерево, кроме `git add` перед сравнением diff, который и так выполняет commit узла; автоматических повторов нет |

## Независимое ревью

Первая версия прошла read-only ревью отдельным агентом. Вердикт — FAIL по одной причине: `rejectCosmetic` отклонял настоящие изменения. Путь с выключенным сторожем замечаний не получил. Все замечания исправлены.

| Замечание | Исправление |
| --- | --- |
| `rejectCosmetic` считал косметикой исправление отступа в Python, строки `#count = 1`, `*ptr = x;`, `--flag`, переименование, смену режима, новый пустой файл | Косметикой считается только заведомо косметическое изменение; синтаксис комментариев берётся по расширению; тест на 16 видов правок и 6 видов изменений файлов |
| «Сломал — починил» засчитывалось как прогресс | Сравнение с лучшим достигнутым состоянием |
| Счётчик повторов блокера был недостижим, каждый `resume` добавлял копию в историю | Блокер определяется причиной, областью и commit; повторная остановка продолжает ту же запись |
| При двух остановившихся узлах блокер получал область другого узла; evidence проверок прикладывалось к любой остановке | Область и причину несёт сама ошибка остановки; evidence — только для остановки на проверке |
| Отмена после `resume` выводилась как «прошлая попытка» | Отменённый запуск показывает `Stopped` |
| Строка `Watchdog` выводилась без настроенного порога | Выводится, только если порог задан или сработал |
| Документ не оговаривал, что часть диапазона порога ничего не меняет | Оговорено в руководстве |

Второе ревью снова дало FAIL по той же причине: эвристика с таблицей синтаксисов и блочными комментариями всё ещё принимала настоящие изменения за косметику (универсальный селектор CSS, оператор в начале строки, раскомментирование блока, текст в шаблонной строке, директивы инструментов, значимые пробелы), а редактирование секретов в выводе git портило пути вида `task-management-service`. Исправления 2–7 первого круга ревью подтвердило.

| Замечание второго ревью | Исправление |
| --- | --- |
| major: `cosmeticOnly` возвращал «косметика» на настоящих изменениях | Проверка сужена до однозначного подмножества: строчные комментарии и пустые строки в обычных JS/TS и Python без шаблонных и многострочных строк; директивы инструментов, блочные комментарии, любые пробелы и все прочие типы файлов не судятся; вывод git читается без редактирования; тест на 34 вида правок, включая все контрпримеры ревью |
| Разные ошибки уровня запуска склеивались в один блокер со старым текстом | Текст входит в тождество блокера без собственной области; сводка показывает последний текст |
| Ветки «бинарный файл» и «смена режима» не исполнялись тестами; нет теста на два остановившихся узла | Добавлены тесты. Разбор diff, к которому относилась ветка «бинарный файл», позже удалён вместе с разбором комментариев |
| Остановка `behavior_blocked` теряла evidence | Ошибка несёт область `verification` |
| Отменённый запуск без записи блокера печатал `Pending blocker` | Печатает `Stopped` |

Третье ревью: FAIL по той же причине. Проверка всё ещё принимала за косметику настоящие правки в строчных комментариях: директивы, которых не было в перечне (`// nosemgrep`, `# pyright:`, `// $FlowFixMe`), и исполняемое содержимое (`//= require` в Sprockets, ячейки Databricks, зависимости PEP 723). Тест смены режима файла не работал бы на Linux.

| Замечание третьего ревью | Исправление |
| --- | --- |
| major: директивы вне перечня и исполняемое содержимое в комментариях считались косметикой | Комментарии больше не судятся совсем. Косметика — только отсутствие изменений или различие в пустых строках; перечень директив удалён |
| major: тест смены режима менял только индекс, на Linux `git add -A` возвращал режим файла | Тест меняет и индекс, и режим файла |
| Строка `// */` внутри блочного комментария, строка, продолженная `\`, JSX в `.js` | Комментарии не судятся; файл с продолженной строкой не судится |
| Файл больше 16 МиБ ронял проверку; имя файла `x.constructor` давало `TypeError` | Размер читается до содержимого; любая ошибка оценки означает «настоящая работа»; расширение ищется в `Map` |
| После повторной остановки сводка теряла имя упавшей проверки | `progress.md` печатает последний текст и, если он другой, первый (`First reported as`) |

Четвёртое ревью: FAIL по той же причине. Правило «только пустые строки» тоже называло косметикой настоящие правки: замену байта вне UTF-8 (diff читался как текст), пустую строку, от которой зависит `prettier --check`, сдвиг hashbang и объявления кодировки.

| Замечание четвёртого ревью | Исправление |
| --- | --- |
| major: три класса настоящих правок считались косметикой | Распознавание косметики удалено. Опция переименована в `rejectUnchanged` и отклоняет только узел, у которого подготовленное дерево совпадает с базой (`git diff --cached --quiet`); исключение для documenter снято |
| JSX в `.js`, файл без расширения с именем `py`, хвост файла | Неприменимо: содержимое файлов больше не разбирается |

Пятое ревью: **PASS**, замечания minor; исправлены: сдвиг указателя подмодуля считается изменением при любой настройке `diff.ignoreSubmodules`, уточнены число тестов и две формулировки.

Теста на то, что остановка `behavior_blocked` получает evidence, нет.

## Изменённое существующее поведение

- В Run появились поля `blocker` и `watchdog`. `run.error` ведёт себя как раньше.
- `progress.md` для запусков с `run.blocker` печатает `Current blocker` или `Last error (previous attempt…)` вместо `Pending blocker`. Для запусков без этого поля строка прежняя.
- Без блока `watchdog` в конфигурации новых остановок нет.

## Что не сделано

- **Распознавание косметических правок.** По тексту изменения его нельзя сделать без отклонения настоящей работы; см. раздел о ревью.
- **Очередь `maintenance`, Maintenance PR и Health Budget.**
- **Эскалация** со сменой подхода, специалиста или плана: сторож только останавливает.
- **Адаптер ai-memory** (scope ③): сервиса и его закреплённой версии в репозитории нет.
- **Пороги по типу задачи** и прогресс внутри одной команды проверки.
- **Блокер в `kodo audit`**: он виден в `kodo status` и `progress.md`.
- **Анализ Gemini и оценка Jev** перед этапом не выполнялись: в этой среде нет настроенного Kodo runtime с провайдерами.

## Ограничения

- Порог `stalledRounds` считает раунды проверки запуска, а не попытки узла.
- Эффективный бюджет ремонтов ограничен профилем режима, поэтому при `standard` порог 2 совпадает с исчерпанием бюджета 3.
- Косметические правки не распознаются: `rejectUnchanged` отклоняет только узел без изменений.
- Все свидетельства этапа — offline.
