## Соответствие приёмке

| Сценарий | Чем подтверждено |
| --- | --- |
| Timeout после успешной загрузки | Новый тест: `gh release create` выполняется и затем падает по таймауту; повтор завершает тот же черновик, создание одно, повторной загрузки нет, публикация одна |
| Timeout после успешного слияния | Новый тест: `gh pr merge` выполняется и затем падает; слияние одно, исход `reconciled` |
| Сбой между удалённым действием и сохранением квитанции | Новый тест: сохранение квитанции слияния падает; журнал показывает `uncertain`; `resume` читает удалённое состояние и не сливает второй раз |
| Double-publish | Существующие: повторный `releasePackage` не публикует; прерванный черновик завершается без второго создания; чужой черновик не меняется |
| Stale CI, tag, checksum | Существующие: устаревшее ревью отклоняется до push; висящий тег на другом commit; изменённый пакет при сверке опубликованного выпуска |
| Failing installed CLI | Существующий: пакет, не прошедший проверку установленного CLI, не публикуется. Новый: проверка привязана к SHA-256 артефакта и при восстановлении идёт на скачанных байтах |
| Несовместимая миграция | Существующие: Project Store и job store отклоняют неизвестную версию схемы |
| Read-back прежде повтора; защиты веток сохранены | Логика чтения удалённого состояния не менялась; `--admin` не используется, обязательные проверки читаются из защиты ветки |
| Deployment без adapter → `not_configured` | `deploymentStatus`: `not_configured` или `not_run`, `passed` всегда `null` |

Реальный Release на этом этапе не публиковался: это задача этапа 13.

## Независимое ревью

Первая версия прошла read-only ревью отдельным агентом. Вердикт — FAIL по одной причине: журнал мог записать `absent` для слияния, которое не опровергнуто. Регрессий самой доставки ревью не нашло: повторного внешнего действия и потери квитанции новый код не даёт; все девять строк таблицы «что уже было» сверены с кодом.

| Замечание | Исправление |
| --- | --- |
| major: `absent` писался, когда команда слияния вернулась, а PR ещё открыт, и когда PR слит, но commit ещё пуст | `absent` — только при упавшей команде и неслитом PR; иначе исход не пишется, операция остаётся `uncertain`; два теста |
| Публикация, выполненная этим вызовом над найденным черновиком, называлась `reconciled` | `confirmed`, если этот вызов сделал выпуск публичным |
| Повторное чтение понижало `confirmed` до `reconciled` | Подтверждённое не понижается без нового намерения |
| Нет исхода, когда PR уже слит при листинге | Записывается `reconciled` |
| Сбой записи исхода ронял уже состоявшуюся доставку; сводка журнала в Engine могла сорвать сохранение состояния | Исходы и сводка — наблюдение, их сбой не меняет результат; намерение остаётся обязательным; два теста |
| Намерение выпуска писалось и для уже опубликованного выпуска | Не пишется, если менять нечего |

Не исправлено, записано как ограничение: операция остаётся `uncertain`, если после намерения запуск остановился по другой причине, и гипотеза о ней может относиться к прошлой попытке; `confirmed` для PR ставится по URL команды без отдельного чтения; отказ до публикации выпуска не пишет `absent`. Тестов уровня Engine для сводки журнала и отрицательного теста `assertSmokeBinding` нет.

## Изменённое существующее поведение

- Квитанция проверки установленного пакета получила обязательное для новых выпусков поле `artifactSha256`. Это изменение контракта: схема квитанции в `tests/delivery.test.mjs` обновлена.
- Доставка пишет события `delivery.operation`.
- В Run с включённой доставкой появились поля `deliveryOperations` и `deployment`.

## Что не сделано

- **Batch merge** независимых изменений и изоляция сломанного батча.
- **Жизненный цикл выпуска** с состояниями `monitored` и `rollback-needed`, changelog из принятых изменений.
- **Адаптеры развёртывания**, canary, health и rollback.
- **Единая квитанция выпуска**: `run.release` и `run.delivery.release` остаются двумя копиями.
- **Версионирование и backup основной базы состояния**; backup job store.
- **Связь задания очереди с операцией доставки**: журнал привязан к Run, а не к заданию durable jobs.
- **Анализ Gemini и оценка Jev** перед этапом не выполнялись: в этой среде нет настроенного Kodo runtime с провайдерами.

## Ограничения

- Все проверки используют настоящий локальный Git и подставной `gh`. Работа с настоящим GitHub этим этапом не подтверждена.
- Журнал наблюдает за доставкой и не принимает решений.
