# Проверки Kodo

Последний полный локальный прогон: `npm run check`, **144 passed, 1 Unix-only skipped, 0 failed**, exit 0 (Windows, Node.js 24). Дополнительная проверка миграции после записи включена в отдельный зелёный security-прогон. `node scripts/package-smoke.mjs` отдельно проверяет упаковку, установку и команды установленного Kodo; тот же шаг включён в матрицу CI Windows/Linux.

Состояние на 2 ноября 2026 года. Документ отделяет проверку реализации, короткие обращения к сервисам и завершённую приёмку пайплайна. Перед выпуском результаты должны относиться к его конкретному commit.

## Автоматические проверки

```powershell
npm run validate
npm test
```

Обычный CI не использует платные API, подписочные сессии или production-репозитории. Тесты провайдеров используют контролируемые ответы и ошибки; проверки Git/worktree выполняются на временных репозиториях.

Критические сценарии: восстановление состояния, идемпотентная доставка, отмена, лимит подписки, недоступность Jev и источника исследования, неверный план/ответ, пересечение областей записи, сохранение пользовательских изменений, повторная проверка после ревью и изменения `main`, запрет устаревшего выпуска и отсутствие секретов в артефактах.

Подтверждён полный локальный прогон **103 тестов** на Windows. После него добавлен отдельный набор `node --test tests/default-init.test.mjs`: **3 теста прошли**, без пропусков. Это два результата; итоговое число общего прогона обновляется после проверки текущей ревизии.

Новые проверки запускают настоящий CLI во временном стороннем проекте. Они подтверждают установку всех 13 стандартных навыков и навыка запуска для Codex, Claude Code и OpenCode, сохранение существующей конфигурации при повторе и остановку до записи файлов при пользовательском изменении установленного навыка.

В поставку включены **13 закреплённых компонентов и 183 оригинальных файла** из upstream-репозиториев. `third-party-skills.lock.json` хранит commit, происхождение, условия лицензии и SHA-256 каждого оригинала. Локальные проверки проверяют целостность, ресурсы обёрток и решения о применимости всех 13 компонентов на каждом этапе. Отдельный интеграционный сценарий проверяет сохранение опыта только после успешных проверок и ревью и его передачу следующему запуску.

Полный прогон на Linux и проверка установленного пакета на обеих платформах фиксируются отдельно по результатам CI и выпуска. Локальный Windows-прогон их не заменяет.

Этот прогон подтверждает обе подписки и восстановление состояния, но не заменяет PR и выпуск самого Kodo.

Приёмка первого пайплайна включает:

1. Сквозной запуск через Codex по подписке.
2. Сквозной запуск через Claude Code по подписке.
3. Запуск с явно разрешёнными обеими подписками.
4. Прерывание и продолжение без дубликатов внешних действий.
5. Две задачи Kodo с отдельными PR, объединением и проверенным выпуском CLI.

Эти сквозные испытания и выпуск **ещё не приняты**. Результат каждого фиксирует runId, модель/клиент, исходный и итоговый commit, проверки, PR, merge и выпуск. Недоступное действие помечается как блокер или непроведённая проверка. Готовность не объявляется, если необходимая стадия не состоялась.

Для выпуска нужны GitHub Release с `.tgz`, SHA-256 и release notes, установка именно опубликованного пакета в изолированное окружение и проверка команды `kodo`. До появления такого отчёта опубликованный и проверенный выпуск не заявляется.

MCP-шаблоны проверяются как JSON/TOML. Синтаксическая проверка не подтверждает живые соединения GitHub MCP, браузера или Supabase.
