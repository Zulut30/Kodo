# Проверки Kodo

Этот документ отделяет доказательства реализации от планов и доступности сервисов. Для готовности исполняемого пайплайна нужны результаты текущего кода.

## Автоматические проверки

```powershell
npm run validate
npm test
```

Обычный CI не использует платные API, подписочные сессии или production-репозитории. Тесты провайдеров используют контролируемые ответы и ошибки; проверки Git/worktree выполняются на временных репозиториях.

Критические сценарии: восстановление состояния, идемпотентная доставка, отмена, лимит подписки, недоступность Jev и источника исследования, неверный план/ответ, пересечение областей записи, сохранение пользовательских изменений, повторная проверка после ревью и изменения `main`, запрет устаревшего выпуска и отсутствие секретов в артефактах.

Количество успешных проверок, команды и версии окружения добавляются после завершённого прогона. Код завершения и наблюдаемые результаты должны относиться к той ревизии, которая рассматривается для выпуска.

## Реальные проверки

`kodo doctor --live` отдельно проверяет подключения. Успех короткого обращения подтверждает доступность этого обращения; он не доказывает полное выполнение задачи, восстановление сессии или стабильность лимитов.

Приёмка первого пайплайна включает:

1. Сквозной запуск через Codex по подписке.
2. Сквозной запуск через Claude Code по подписке.
3. Запуск с явно разрешёнными обеими подписками.
4. Прерывание и продолжение без дубликатов внешних действий.
5. Две задачи Kodo с отдельными PR, объединением и проверенным выпуском CLI.

Результат фиксирует runId, модель/клиент, исходный и итоговый commit, проверки, PR, merge и выпуск. Недоступное действие помечается как блокер или непроведённая проверка. Готовность не объявляется, если необходимая стадия не состоялась.

## Историческая основа каталога

До добавления движка локальная проверка каталога на Windows с Node.js 24.19.0 и npm 12.0.2 завершилась с 25 успешными тестами без пропусков. Были проверены зависимости, адаптеры, установка/повторная установка, защита изменённых файлов, откат имитированной ошибки записи, junction и CLI.

В том временном проекте Codex CLI 0.163.0 и OpenCode 1.18.32 обнаружили 13 навыков; OpenCode загрузил роль архитектора. Это подтверждало обнаружение компонентов до переименования и не является доказательством текущего исполнения Kodo. Обнаружение Claude Code и модельная задача тогда не проверялись.

MCP-шаблоны проходили проверку синтаксиса JSON/TOML. Реальные соединения GitHub MCP, браузера и Supabase в ту проверку не входили. После изменения форматов или зависимостей соответствующие результаты необходимо получать заново.
