# Контекст, вывод и непрерывная очередь Kodo

Kodo сокращает повторяемый начальный контекст и допускает готовые задачи без ожидания всей группы. Обязательные требования, изоляция worktree, лимиты подписок, проверки и независимое ревью сохраняются. Это поведение текущих исходников; его наличие в опубликованном пакете проверяется отдельно. [Решение и альтернативы](decisions/0004-context-output-and-ready-queue.md).

## Небольшие задачи и готовые зависимости

В standard/deep планировщик выделяет связные результаты по модулям с явными интерфейсами, acceptance и узкими `writePaths`. Тесты и документация зависят только от необходимых им результатов. Для маленькой правки искусственное дробление не нужно; quick по-прежнему рекомендует одно developer-задание с нужными tests/docs и сохраняет свой бюджет.

`runReadyQueue` управляет допуском задач, а Engine владеет моделями, сохранённым состоянием, worktree и интеграцией. Пример: независимые A и B работают одновременно; после завершения и интеграции A зависимый C может начать работу, пока B ещё выполняется. Одного `complete:true` от A недостаточно: зависимость должна иметь сохранённый статус `integrated`.

Каждый worker получает отдельное worktree и сессию. Конкурентность ограничена настройками запуска и глобальными leases: не более двух native-сессий на подписку. Совместная работа требует `parallel:true` и в плане, и в решении маршрутизации, а также непересекающихся областей записи. Область остаётся занятой до завершения последовательной интеграции. Jev получает снимок реально готовых/активных соседей; завершённый предок и заблокированный потомок не считаются конкурентами. Сохранённый выбор последовательного выполнения не отменяется ради скорости.

Маршрутизация ожидающей задачи повторно не вызывается без необходимости. Уже завершённая задача восстанавливается и интегрируется без нового выполнения. При ошибке прекращается новый допуск, уже начатая работа дожидается завершения; успешные результаты сохраняются и могут интегрироваться. После ошибки merge другой результат не накладывается поверх незавершённой интеграции. При отмене новые интеграции не начинаются. Возвращается исходная типизированная ошибка; некорректный граф или конечный тупик дают явную ошибку вместо зависания.

## Компактный контекст с полными evidence

Политика навыков сохраняет заголовок `Kodo default skill policy v1, stage STAGE`, все 13 решений с причиной и provenance, полные применимые адаптеры Kodo и абсолютные ссылки в read-only пакет. Длинные upstream-материалы читаются по необходимости. Проверка всех pinned resources выполняется заново при загрузке политики; React/monorepo-условия и полномочия координатора остаются прежними. [Политика навыков](DEFAULT-SKILLS.md).

Engine сначала фиксирует один отредактированный по известным секретам снимок полных данных вне Git, затем строит сводку именно этого снимка:

| Передаваемая часть | Предел и сохраняемые сведения |
| --- | --- |
| Plan evidence | По умолчанию 12000 UTF-8 байт; статус анализа/исследования, риски, ошибки, метаданные источников и ссылки на полные данные |
| Evidence для worker | Компактная planning-сводка до 4000 байт, отдельно от обязательного контракта, policy и tool guidance |
| Review evidence | По умолчанию 16000 байт; base/head, команды и exit codes, статусы checks, manifest путей либо точное число пропущенных, план/diff в доступном бюджете |
| Контракт нового узла | До 12000 байт сериализованного обязательного ядра: описание, scope, acceptance, interfaces, constraints, зависимости и параметры узла |
| Необязательные сведения узла | До 3000 байт: краткие прямые зависимости, цель, анализ и релевантные ссылки |

Обязательное ядро узла не обрезается по полям. Слишком большой новый контракт отклоняется с `task_contract_too_large` и предложением связного разбиения. Если старый сохранённый план превышает лимит, worker получает явную обязательную ссылку на полный контракт и должен прочитать его до работы.

Сводки — детерминированный корректный JSON с сохранением Unicode. Потери внутри сокращаемых полей отражаются в `omitted`; сырые source bodies, standards и история не входят в allowlist сводки. Неизвестное, неуспешное, пропущенное и повреждённое evidence не становятся PASS. Невместимые обязательные команды/ссылки вызывают `context_budget`. Маленький вход может вырасти из-за метаданных; размер не обязан уменьшаться.

Полезные проверенные знания проекта сохраняются: до трёх кратких `verifiedLessons` с run/head и summary до 200 Unicode-символов, только при успешных checks и review, привязанных к тому же head. Бюджет может исключить целые записи с явным счётчиком. Полные `priorLessons` доступны через analysis evidence; сырые repair/provider histories в сводку не копируются. Нового хранилища или модельного вызова для этого нет.

Полные REDACTED analysis/research, node contracts, review/diff и вывод checks находятся в приватном `runs/<runId>/evidence/`. JSON имеет content-addressed имя и base/head; ссылка содержит SHA-256, размер и head. Engine проверяет читаемость, содержимое и привязку до и после native-сессии, а полные command logs — также перед повторным использованием checks. Подмена или исчезновение дают `evidence_integrity`, сохраняя незавершённую работу без расхода repair/research на исправление кода. Старый check без полного `outputPath` имеет только исторический отрывок: отсутствующий полный вывод не восстанавливается из сводки. [Приватность](SECURITY.md#приватные-evidence-и-rtk).

## RTK: только поддерживаемый локальный вывод

Managed `rtk-ai/rtk` OSS **1.1.0**, revision `753a3b0e939f2e4490fc24e3a1984010f40a103c`, входит десятым optional tool. Registry остаётся из 33 компонентов, default skills — из 13. Закреплены Windows x64 MSVC ZIP и Linux x64 musl TAR.GZ с SHA-256; иных RTK assets в каталоге нет. [Pins и установка](UI-TOOLS.md#rtk-и-вывод-shell).

После получения subscription lease Engine один раз разрешает и проверяет инструменты для сессии; результат используется для её guidance и environment. Следующая сессия проверяет целостность заново. Готовый managed RTK добавляется перед унаследованным PATH только native worker-сессии. Приватный `RTK_DB_PATH` выделяется вне Git, `RTK_RECALL=0`, `RTK_TEE=0`, `RTK_TELEMETRY_DISABLED=1`. Подписочные HOME/auth не перенаправляются.

RTK вызывается явно для проверенных человекочитаемых команд, например `rtk git status` или `rtk git diff --stat`. Поддержку конкретной команды нужно проверить; при отсутствии/неподдерживаемости инструмента используется исходная команда без установки на каждую сессию. Автоматического переписывания shell через native hooks нет. App/desktop host сам по себе не наследует env отдельного native worker: нужен переданный координатором environment и точный managed binary.

JSON, Git porcelain, `-z`/NUL, протоколы и любые данные для парсера остаются сырыми. Generic `rtk test` для Node `node:test`/TAP не применяется: реальная отрицательная fixture потеряла полезную диагностику при сохранённом exit 1. Команды координатора, полный `npm run check`, CI, UI/security и доставка выполняются без RTK. Если фильтр скрывает ошибку, исходную команду повторяют без фильтра и сохраняют полный отредактированный вывод приватно. Утрата диагностики не считается экономией.

Установкой и live probes владеет координатор. Глобальный пользовательский RTK 0.50.0 не заменяется; `init`, config-save, глобальные hooks, обход hook trust и `rtk-proxy` не используются. RTK может читать существующий global config; Kodo задаёт приватные tracking/recall/tee/telemetry overrides, не сохраняет изменения global config и не меняет маршрутизацию моделей. GPT/Claude остаются в подписочных клиентах.

## Что измерено локально

Квитанция `efficiency-measurements.json` от 3 ноября 2026 года: одинаковые сохранённые входы, одинаковые project/root paths для policy, фактические UTF-8 длины, `modelsCalled:0`. Это отдельные части начального контекста/вывода. Исторический inline baseline plan/review не включает новые метаданные; он не равен `contextOriginalBytes` нового runtime. Приватные источники и границы проверок перечислены в [VALIDATION](VALIDATION.md#контекст-очередь-и-rtk).

| Часть | До, байт | После, байт | Сокращение |
| --- | ---: | ---: | ---: |
| Policy: plan | 38589 | 16303 | 57,75% |
| Policy: developer | 26946 | 12845 | 52,33% |
| Policy: tester | 26971 | 13017 | 51,74% |
| Policy: review | 49185 | 19988 | 59,36% |
| Inline analysis/research для плана | 108524 | 11770 | 89,15% |
| Inline review evidence | 181408 | 14892 | 91,79% |
| Managed RTK: `git log -20` | 8121 | 2952 | 63,65% |

Во всех policy сохранились 13 решений. В Git-проверке обе команды завершились с exit 0, семь коротких commit IDs сохранились. В отрицательной Node/TAP fixture raw 4253 байта превратились в 100, оба exit 1, но диагностический sentinel исчез: результат исключён из принятой экономии.

В runtime `promptBytes` — размер окончательного redacted `request.prompt` с policy/tool guidance для конкретной попытки, включая типизированный неуспех провайдера. `contextOriginalBytes`/`contextSentBytes` — размеры переданной компактору части и её JSON-сводки, когда они известны. Старые/неизмеренные значения остаются `null`; агрегаты имеют показатели полноты. Это не размер всей native-переписки, скрытого/system-контекста, прочитанных клиентом файлов или backend-запросов.

Проценты строк не складываются и не являются снижением времени разработки, общего token usage, квоты или цены подписки. Даже `bytes/4`, если используется для ориентира, остаётся приблизительной оценкой, а не измеренными токенами. Native usage/cache semantics не менялись; неизвестные total quota, HTTP counts и subscription USD не выводятся из байтов.

## Проверенные уроки и оставшиеся границы

| Наблюдение и причина | Исправление и предотвращение повторения |
| --- | --- |
| Node/TAP фильтр сохранил exit, но скрыл причину ошибки | Оставлять TAP сырым; проверять отрицательную диагностику, а не только размер/exit |
| Асинхронное сохранение допускает изменение исходных данных между операциями | Компактировать тот же зафиксированный redacted snapshot; Engine-регрессия проверяет изменение research во время записи |
| Content-addressed имя само по себе не предотвращает подмену файла | Проверять hash/head до/после сессии и перед reuse checks; `evidence_integrity` не превращать в ремонт кода |
| Проверка tool inventory до ожидания lease преждевременна | Разрешать после admission, переиспользовать только внутри сессии, проверять заново в следующей |
| Формулировка routing о любой работе могла считать предков/потомков конкурентами | Передавать готовый/активный frontier и согласованные критерии; сохранять действительное typed решение Jev |
| Windows PowerShell input мог повредить Unicode artifact path | Явный UTF-8 при передаче пути; отдельная boundary-регрессия в D |

Локальные Engine/QA проверки используют реальные временные Git/filesystem/worktree и подменённые native providers. Отдельный новый native environment/auth probe подтвердил доступность подписочной авторизации Codex и Claude Code, managed `rtk 1.1.0 --version` с exit 0 и приватные overrides; `modelsCalled:0`. Это не новый Claude inference/E2E и не provider-проверка всего пайплайна.

Матрица моделей остаётся отложенной: новых сравнений и победителя нет. Сохранены режим, явный `--model`, меньшие бюджеты, head-bound checks, свежие включённые gates, независимое review и branch protections. Общий `npm run check`, CI, итоговое review, package/release smoke и deployment этого изменения на этапе F ещё не подтверждены. Видимые worker-чаты обслуживает текущий частный host-adapter координатора через поддерживаемые app tools; универсального desktop backend CLI нет. [Методика benchmark](BENCHMARK.md), [контракт runtime](RUNTIME.md).
