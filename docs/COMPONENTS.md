# Добавление компонентов

`registry.json` — источник списка компонентов и их зависимостей. Каждый компонент имеет `id`, `type`, `version`, `description`, `entry`, `requires`.

```json
{
  "id": "skills/api-review",
  "type": "skill",
  "version": "0.1.0",
  "description": "Проверка контрактов HTTP API",
  "entry": "SKILL.md",
  "requires": []
}
```

Папка совпадает с id: `skills/api-review/`. Допустимые типы: skill, agent, pipeline, mcp, preset. Соответствующие entry: SKILL.md, AGENT.md, pipeline.json, README.md, PRESET.md. Идентификаторы используют строчные латинские буквы, цифры и дефисы; версии имеют вид X.Y.Z. Каждая зависимость обязана существовать; циклы отклоняются.

## Навык

Создай `SKILL.md` с frontmatter из двух однострочных полей:

```markdown
---
name: api-review
description: Проверяй контракт HTTP API при запросе на ревью эндпоинтов.
---

Инструкции, которые помогают выполнить конкретную задачу.
```

Валидатор исходных навыков поддерживает этот ограниченный формат frontmatter, а не весь синтаксис YAML. Не используй в description переносы строк, `: ` или символы с особой семантикой YAML. Для дополнительных материалов можно добавить `references/`, `assets/` или `scripts/`: всё содержимое компонента копируется с сохранением относительных путей. Ссылки на внешние файлы не копируются; symlink запрещены.

Описание отвечает за выбор навыка. Сам текст должен содержать полезные решения и критерии, а не общую декларацию «ты эксперт». Не приписывай наличие инструментов и не расширяй разрешения пользователя.

## Роль

Создай `agents/<name>/AGENT.md`. Адаптер генерирует имя `kodo-<name>`. Для Claude Code создаётся frontmatter name/description, для OpenCode — description/mode: subagent. В Codex роль представлена навыком. Модель, credentials и разрешения глобально не задаются.

## Пайплайн

Создай `pipelines/<name>/pipeline.json` с `goal` и непустым `steps`. Этап имеет уникальный `id`, один из `agent`/`skill`, а также непустые `task` и `output`.

```json
{
  "goal": "Проверить API и передать подтверждённые замечания.",
  "steps": [
    {
      "id": "review",
      "skill": "skills/api-review",
      "task": "Проверь контракт и совместимость эндпоинтов.",
      "output": "Замечания со сценариями воспроизведения."
    }
  ]
}
```

Укажи все используемые этапами роли и навыки в `requires` записи registry. При установке адаптер создаёт SKILL.md, копирует manifest и инструкции зависимостей в `references/`. Файл навыка зависимости переименовывается в `INSTRUCTIONS.md` внутри references, чтобы не создавать вложенную точку обнаружения.

## Пресет и MCP

Пресет содержит `PRESET.md` с контекстом стека и список комплектующих в `requires` registry. Адаптер создаёт навык `kodo-preset-<name>`; пресет не генерирует исходники приложения.

MCP-компонент содержит README и шаблоны `codex.toml`, `claude-code.json`, `opencode.json`. Они копируются как данные и автоматически не применяются. JSON проверяется синтаксически; соединение, доступ и версии сервера нужно проверять отдельно.

После добавления запусти `npm run validate`, затем `npm test`. Для изменения установщика добавляй проверки наблюдаемого поведения во временных проектах. Не запускай реальные AI-модели или production-сервисы в стандартных тестах.

## Исполняемый процесс Kodo

`skills/kodo-build-feature` — вход из чата в движок исполнения. Он получает анализ и runId, затем передаёт структурированный план текущей модели через `resume --plan`.

Контракт плана описан в [RUNTIME.md](RUNTIME.md). Изменяя его, обновляй JSON Schema, навык, валидные/невалидные примеры и проверки восстановления. Имена стадий, ответы моделей и код завершения процесса сами по себе не являются доказательством выполнения задачи: результат должен ссылаться на проверенный commit и наблюдаемые проверки.
