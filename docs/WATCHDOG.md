# Сторож прогресса и текущий блокер

Этап 10 отвечает на два вопроса: движется ли запуск и что именно мешает ему сейчас. Решения описаны в [ADR-0012](decisions/0012-progress-watchdog.md).

Сторож только наблюдает и останавливает. Код, план и доставку он не меняет.

## Что считается прогрессом

Прогресс — изменение принятого критерия между двумя раундами проверки:

| Причина | Факт |
| --- | --- |
| `node_integrated` | Интегрирован ещё один узел плана |
| `check_passed` | Больше команд проверки завершилось с кодом 0 |
| `behavior_gate_passed`, `behavior_findings_resolved` | Behaviour gate прошёл или находок стало меньше |
| `gate_passed` | Прошёл ещё один из gates UI, security, architecture |
| `review_passed`, `review_findings_resolved` | Ревью прошло или находок стало меньше |

Новый commit, изменённый текст ошибки, число сессий, строк, токенов и вызовов инструментов прогрессом не считаются: сторож их не наблюдает.

## Настройка

```json
{ "watchdog": { "stalledRounds": 2, "rejectCosmetic": true } }
```

Блок необязателен. Без него действуют только прежние правила: одинаковая сигнатура сбоя на том же commit (`no_progress`) и бюджет `repairRounds`.

| Ключ | Диапазон | Смысл |
| --- | --- | --- |
| `stalledRounds` | 1–5, по умолчанию выключено | Остановить запуск после стольких раундов ремонта подряд без прогресса |
| `rejectCosmetic` | по умолчанию `false` | Не засчитывать узел `developer` или `tester`, который изменил только комментарии и пробелы или не изменил ничего |

При `stalledRounds: 2` запуск останавливается после третьего неудачного раунда: первый задаёт точку отсчёта, два следующих не дали прогресса. Причина остановки — `no_verified_progress`. Порог — правило диагностики, а не гарантия: он не отличает трудную задачу, которая продвигается внутри одной команды проверки, от топтания на месте. Для таких задач порог поднимают или не задают.

Эффективный бюджет ремонтов по-прежнему ограничен профилем режима: 1 для `quick`, 3 для `standard`, 5 для `deep`.

Состояние сторожа (`run.watchdog`) сохраняется вместе с запуском: счётчик переживает перезапуск процесса и паузу по квоте. Шаг с тем же ключом раунда повторно не считается. Обычный `resume` остановленного запуска новых раундов не даёт; новый отсчёт начинает только явный `--retry-failed`.

`rejectCosmetic` сравнивает изменение узла с его базой без учёта пробелов и пустых строк. Узел с ролью `documenter` не проверяется: его результатом могут быть комментарии.

## Текущий блокер

Когда запуск останавливается в состоянии `blocked` или `waiting_limits`, в `run.blocker.current` записывается, что именно его остановило:

```json
{
  "code": "no_verified_progress",
  "scope": "verification",
  "message": "Проверки не пройдены: …",
  "signature": "…",
  "firstSeen": "2026-11-10T10:00:00.000Z",
  "lastSeen": "2026-11-10T10:00:00.000Z",
  "occurrences": 1,
  "headSha": "…",
  "hypotheses": ["Several repair rounds changed no accepted criterion: …"],
  "evidence": [{ "sha256": "…", "kind": "check" }]
}
```

- `scope` — `verification`, id узла плана или `run`.
- `hypotheses` — кандидаты в объяснение, выведенные из записанных фактов (код остановки, пометка `regression` или `pre_existing`, сбой behaviour gate). Это не вердикт.
- `evidence` — хэши evidence последних проверок и оракулов; сами файлы лежат в каталоге evidence запуска.

Тот же блокер при повторной остановке не дублируется: растёт `occurrences`. Другой блокер переносит прежний в `run.blocker.history` (до 20 записей) с исходом `replaced`.

При каждом новом входе в запуск текущий блокер становится историей с исходом `resumed`. Сохранённая ошибка прошлой попытки (`run.error`) остаётся для совместимости, но текущим блокером больше не считается. При успехе текущего блокера нет.

## Сводка восстановления

`progress.md` в каталоге запуска показывает:

```
Current blocker: no_verified_progress [verification] Проверки не пройдены: …
Seen 1 time(s): first …, last …; commit …
- Hypothesis: Several repair rounds changed no accepted criterion: …
Evidence: check <sha256>
Earlier blockers: 1
- resumed 2026-11-10T11:00:00.000Z: quota [run] …
Watchdog: 2 round(s) without verified progress; stopped at limit 2
```

Пока идёт продолжение запуска, старая ошибка выводится строкой `Last error (previous attempt, not the current blocker)`. Запуски, сохранённые до этапа 10, по-прежнему показывают `Pending blocker`.

`kodo status RUN_ID` печатает сохранённый запуск целиком, включая `blocker` и `watchdog`.
