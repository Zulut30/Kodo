# Поиск по каталогу: `kodo list --search`

Фильтр `--search` сужает вывод команды `list` до компонентов, у которых искомый текст встречается в `id` или `description`.

## Синтаксис

```
node cli/index.mjs list [skill|agent|pipeline|mcp|preset] [--search TEXT] [--json]
```

- `TEXT` — одно значение; если оно содержит пробелы, возьмите его в кавычки.
- Без `--search` `list` работает как раньше.
- Тип указывается в единственном числе (`skill`, а не `skills`) и не более одного.

## Что и как ищется

- **Поля:** `id` (например, `agents/qa-engineer`) и `description`. Остальные поля (`type`, `version`, `entry`, `requires`) не участвуют.
- **Совпадение — по подстроке.** Компонент подходит, если `TEXT` входит хотя бы в одно из двух полей. Границы слов не учитываются.
- **Регистр не важен**, в том числе для кириллицы: `ПРОВЕРК`, `проверк` и `Проверк` дают одинаковый результат. Сравнение выполняется после Unicode-нормализации NFC и приведения к нижнему регистру.
- Пробелы по краям `TEXT` отбрасываются; внутренние пробелы сохраняются.

## Сочетание с другими параметрами

- **С типом:** фильтры работают вместе (логическое «И») — сначала тип, затем текст.
- **С `--json`:** выводится массив тех же объектов, что и у `list --json` без поиска (`id`, `type`, `version`, `description`, `entry`, `requires`), только отфильтрованный.

## Порядок и повторы

Результаты идут в порядке `registry.json`; поиск порядок не меняет. Каждый компонент выводится не более одного раза, даже если искомый текст есть и в `id`, и в `description` (`id` в реестре уникальны).

## Пустой результат

- С `--json` выводится `[]`, код возврата `0`.
- Без `--json`, если ничего не найдено, вывод пустой, код возврата `0`.

## Ошибки

Ошибки печатаются в stderr в виде `Ошибка: …`, код возврата — `1`.

| Ситуация | Сообщение |
| --- | --- |
| `--search` в конце команды или перед другим параметром (`--search --json`) | `Требуется значение --search` |
| Значение из одних пробелов (`--search "  "`) | `Требуется значение --search` |
| `--search` указан дважды | `Повторный параметр: --search` |
| Неизвестный тип (`list foo --search a`) или больше одного типа | `Укажи тип: skill, agent, pipeline, mcp или preset` |
| Команда, кроме `list` (`show`, `plan`, `validate`, `install`, `init`) | `Параметр search неприменим к <команда>` |

Значение, начинающееся с `--`, считается отсутствующим.

## Примеры

Английский текст, любой регистр:

```
$ node cli/index.mjs list --search REVIEW
skills/code-review            Проверка изменений кода с доказуемыми замечаниями
skills/differential-review    Стандарт Kodo differential review
```

Совпадение по `id` и `description` одновременно (`nextjs` есть в `id`, `Next.js` — в описании):

```
$ node cli/index.mjs list --search next
presets/nextjs                Комплект для Next.js-проекта
```

Русский текст, регистр не важен:

```
$ node cli/index.mjs list --search "ПРОВЕРК"
skills/code-review            Проверка изменений кода с доказуемыми замечаниями
agents/qa-engineer            Проверка требований и регрессий на наблюдаемых результатах
pipelines/build-feature       Реализация функции от требований до проверки
pipelines/build-website       Создание сайта с проверкой UI и SEO
skills/kodo-build-feature     Выполнение задачи через движок Kodo с анализом планом агентами проверками и доставкой
```

Вместе с типом:

```
$ node cli/index.mjs list agent --search "ПРОВЕРК"
agents/qa-engineer            Проверка требований и регрессий на наблюдаемых результатах
```

Вместе с `--json`:

```
$ node cli/index.mjs list skill --search audit --json
[
  {
    "id": "skills/ui-audit",
    "type": "skill",
    "version": "0.2.0",
    "description": "Аудит интерфейса и пользовательского сценария",
    "entry": "SKILL.md",
    "requires": []
  },
  …
]
```

Пустой результат:

```
$ node cli/index.mjs list --search zzzz --json
[]
```

Ошибка:

```
$ node cli/index.mjs list --search
Ошибка: Требуется значение --search
```
